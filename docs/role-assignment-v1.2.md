### 인프라 (R: 오준서)

기능ID 를 붙이지 않는다 — 기능 명세서 v1.1 의 F-CMN 은 003 까지이고, 없는 ID 를 만들면
명세서와 어긋난다. 화면 섹션과 같은 형태로 R 만 지정한다.

| 항목 | 내용 | 비고 |
|---|---|---|
| CI | PR 에서 3모듈 테스트 실행 (`server` JUnit · `ai-service` pytest · `web` `tsc --noEmit`) | 현재 `.github/workflows/` 에는 리뷰 승인 여부만 보는 `pr-review-guard.yml` 뿐이고 **테스트가 CI 에서 한 번도 돌지 않았다** |
| 로컬 실행 | 세 서비스(:8000 · :8100 · :5173) 동시 기동 절차 | 지금은 문서에 없다. 3주차 통합·리허설 전에 서 있어야 한다 |
| 개발환경 문서 | 필요한 런타임 버전과 함정 | 아래 참고 |
| 데모 환경 | 리허설·시연용 기동 | 9/3~9/6 |

**범위 밖** — 각 모듈 *내부* 툴체인은 그대로 소유자 것이다: `server/build.gradle`·
`settings.gradle`(강희진), `ai-service/requirements*.txt`(윤지석), `web/package.json`·
`tsconfig.json`(오준서 본인). `.github/CODEOWNERS` 는 PM(정세현) 이 유지한다.
린터는 3주 타임박스에서 비용이 이득보다 커서 데모 범위 밖으로 둔다.

**인계 사항 — JDK 17 함정 (2026-08-25 확인).** `server/build.gradle` 이 툴체인을
`languageVersion=17` 로 고정하는데, 이 값이 README·CLAUDE.md 어디에도 없다. macOS 에서
Homebrew 로 깔면 `openjdk@17` 이 keg-only 여서 `/Library/Java/JavaVirtualMachines` 에
링크가 안 걸리고, 그러면 Gradle 툴체인 자동 탐지와 `/usr/libexec/java_home` 이 못 찾는다
(`No locally installed toolchains match`). sudo 없이 넘기는 방법:

```
brew install openjdk@17
# ~/.gradle/gradle.properties
org.gradle.java.installations.paths=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home
```

이 상태에서 `cd server && ./gradlew test` → 67건 통과를 확인했다. 레포에
`settings.gradle` 로 툴체인 자동 다운로드(foojay-resolver)를 넣는 방법도 있는데 그 파일은
강희진 소유이므로 CI 설계와 함께 정하는 게 낫다.

## 2. 사람별 요약

**윤지석 (AI 엔진) — R 5개**
F-EXT-002, F-INT-002, F-SCR-001, F-DET-001, F-DET-002. 개수는 적지만 전부 크리티컬 패스이자 불확실성 최대 구간. 다른 작업 없이 여기에만 집중. 산출물: 프롬프트 세트, 루브릭, 상품 템플릿, 채점 API.

**강희진 (코어 백엔드) — R 6개**
F-INT-001, F-INT-004, F-GTE-001~003, F-CMN-001. 시스템의 등뼈. (F-CMN-002는 정세현에게 이관 — F-GTE-004와 불변 저장 계층이 동일해 한 사람이 소유.) 기능ID에 안 잡히는 무게가 큼: API 컨트롤러 전체, `contracts/` 스키마 소유·변경 관리, Spring 셋업·영속성, `AiServiceClient` 골격, 통합 리드. **첫날 임무: 채점 결과 JSON 스키마(등급·근거 스팬·신뢰도)와 세션 API 계약을 확정해 윤지석·오준서에게 배포** — 이것이 전체 병렬화의 전제. + 평가 라벨러.

**정세현 (데이터·시뮬레이터·증거기록) — R 7개 + 오해 라이브러리 + PM**
F-EXT-001(축소), F-EXT-003, F-SIM-001, F-GTE-004, F-DSH-003, F-CMN-002, F-CMN-003, 오해 라이브러리(F-DET-001의 데이터). 의존성 없는 것이 많아 초반 진도가 가장 빠른 파트. + 제출물·발표 총괄, 일정 관리.
**소유 서사: 이 시스템에 남는 모든 기록과 증거** — 이해 기록(F-GTE-004) + 감사 로그(F-CMN-002) + 접근 정책. 두 기능이 `evidence` 공통 기반을 공유하므로 설계를 한 번만 제대로 한다.
※ 전제: F-EXT-001을 문서 2종으로 타임박스하지 않으면 PM이 병목이 된다.

**오준서 (프론트 + 인프라) — R 3개 + 화면 8종 + 인프라**
F-INT-003, F-DSH-001~002, S-01~S-08, 데모 시연 흐름 총괄. 목 API로 첫 주부터 화면 착수. S-03(인터뷰)과 S-04(시뮬레이터)가 데모 인상의 8할이므로 S-01·S-08은 마지막에.
**인프라 R 추가** — CI(3모듈 테스트), 로컬·데모 실행 환경, 개발환경 문서. 역할표 초판에 담당이 지정돼 있지 않아 기본 소유자(PM)에게 떨어져 있던 몫이다. 데모 시연 흐름을 총괄하는 사람이 실행 환경을 갖는 것이 자연스럽다.

주차는 위 마일스톤에 맞춰 다음과 같이 끊는다.

| 주차 | 기간 | 끝나는 날 기준 |
|---|---|---|
| 1주차 | 8/20(목) ~ 8/26(수) | |

**3주차가 짧은 것이 이 일정의 최대 제약이다.** 9/3~9/6은 나흘이고 그 안에 전원 통합 테스트,
데모 리허설, 제출물·발표 자료가 함께 들어간다. 따라서 **3주차에는 새로 만드는 것을 최소화하고,
2주차에 기반을 끝내 놓는다.**

특히 `evidence` 공통 기반은 F-GTE-004와 F-CMN-002 **두 모듈의 선행조건**이다. 2주차 끝에 나오면
3주차 나흘 안에 기반 위 두 모듈 + 통합 + 제출물을 전부 해야 한다. 그래서 아래와 같이 못박는다.

> **`evidence` 공통 기반은 8/27(목) 착수, 8/29(토) 완료를 목표로 한다.**
> 2주차 항목 중 가장 앞에 둔다. 1주차 정세현 몫(파서·시뮬레이터·오해 라이브러리)이 조기에
> 끝나 생긴 여유를 여기에 쓴다.

**착수 전제는 해소됐다.** 게이트 판정 결과를 세션에 저장하는 것으로 강희진과 합의했다(PR #16).
감사 기준점이 재계산값이 아니라 기록값이어야 한다는 ADR-003 근거다.

| 항목 | 내용 |
|---|---|
| 저장 시점 | `judge()` 가 GateEngine 결과를 받은 직후, 상태 전이와 함께 |
| 필드 | 신호등(`signal`) + 발화한 룰(`ruleTrace`) + 판정 시각(`judgedAt`) |
| 갱신 방식 | 덮어쓰기. 재판정 이력과 해시 체인은 `evidence/` 가 받는다 |
| 추가 위치 | 강희진 F-INT-004 재검증 루프 PR |

필드가 F-INT-004 PR 에 오므로 8/27 시점에 코드가 아직 없을 수 있다. **계약이 확정됐으므로 착수를
막지 않는다** — `evidence` 는 위 세 값을 입력으로 가정해 만들고, 필드가 들어오면 배선만 한다.
그 순서라야 두 사람이 병렬로 움직인다.

**1주차 (8/20~8/26) — 계약과 독립 모듈**
강희진: API·JSON 스키마 계약 확정 배포 → 세션 상태머신. 정세현: 문서 수집 + 파서(F-EXT-001) + 시뮬레이터(F-SIM-001) + 오해 라이브러리. 윤지석: F-EXT-002 추출 프롬프트(정세현 파서 출력 받는 즉시). 오준서: 목 기반 S-02·S-03.

**2주차 (8/27~9/2) — 크리티컬 패스**
윤지석: F-SCR-001 채점 + F-DET-001/002 (라이브러리는 정세현에게서 수령). 강희진: 게이트(F-GTE-001~003) + 재검증 루프(F-INT-004). 정세현: **`evidence` 공통 기반(CanonicalJson·HashChain·ImmutableStore) — 8/27 착수·8/29 완료 목표, 2주차 최우선** → F-EXT-003 검증 리포트 + 합성 세션 생성기 + `rbac_policy.yaml` 초안(강희진과 적용 지점 합의). 오준서: S-04·S-05 + 텍스트 응답 입력(F-INT-003).

**3주차 (9/3~9/7) — 통합·평가·데모**
전원 통합 테스트(메인 데모 시나리오 7단계 관통). 정세현: 평가 파이프라인 실행(라벨링: 정세현+강희진 — 위 §1 정정), 성능 리포트, **`evidence` 위에 F-GTE-004(이해 기록)와 F-CMN-002(감사 로그) 얹기**. 오준서: S-06~S-08 + 데모 리허설. 버퍼: 채점 품질 미달 시 윤지석 프롬프트 개선에 전원 발화 데이터 만들어주기.

## 4. 인터페이스 계약 (소유자)

| 계약 | 공급 → 수요 | 소유 |
|---|---|---|
| 파싱 출력 JSON | 정세현 → 윤지석 | 정세현 |
| RiskItem 스키마 | 윤지석 → 강희진·오준서 | 강희진 |
| 채점 결과 Judgment 스키마 | 윤지석 → 강희진(게이트)·오준서(S-05) | 강희진 |
| 세션 API | 강희진 → 오준서 | 강희진 |
| 시뮬레이터 계산 API | 정세현 → 오준서 | 정세현 |
| 집계 API | 정세현 → 오준서(대시보드) | 정세현 |
| 역할·접근 정책 (`rbac_policy.yaml`) | 정세현 → 강희진(컨트롤러 적용) | 정세현 |

스키마 변경은 소유자 승인 없이 금지. 변경 시 소유자가 수요자 전원에게 통지.

**시뮬레이터 파라미터는 RiskItem 에서 오지 않는다** (v1.2 초판 표기 정정, PR #16 리뷰에서 합의).
`RiskItem.Condition` 은 P6(수치는 원문 인용만) 때문에 `valueText` + `sourceSpan` 뿐이고 배리어·쿠폰·
평가일 같은 구조화 수치 필드가 없다. 시뮬레이터가 `valueText` 를 파싱하면 문면이 조금 달라져도
계산 결과가 달라져 P2(결정론)가 깨지고, 발행사 공시 수치와 대조해둔 검산의 근거가 사라진다.

따라서 데모 범위에서는 `SimulatorService` 가 상품 조건을 문서에서 직접 읽은 상수로 보유한다
(`KIWOOM_4181` — 간이투자설명서 p7·p10, 금투협 청약정보 근거). 구조화된 `ProductTerms` 계약은
후속이며, 시뮬레이터 계산 API 를 `openapi.yaml` 에 등재할 때 함께 정한다.

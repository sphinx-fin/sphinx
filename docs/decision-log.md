# 결정 로그 — PR·이슈에서 확정된 것 전수

소유: 정세현 (`docs/`) · 각 항목의 결정자는 표에 적었다

## 어디까지 훑었나

**기준은 번호가 아니라 시각이다.**

| 훑은 날 | 이 시각까지의 본문·리뷰·코멘트를 다 읽었다 | 옮긴 PR |
|---|---|---|
| 2026-08-25 | `2026-08-25T13:00:00Z` | #52 |
| 2026-08-26 | `2026-08-26T02:02:00Z` | #74 |
| 2026-08-26 (보강) | `2026-08-26T03:00:00Z` — #74 리뷰 대조 + PR #81 결정 반영 | #74 |
| 2026-08-26 (보강) | `2026-08-26T07:00:00Z` — #74 승인 리뷰 대조(머지 6건 반영) | #74 |
| 2026-08-26 (보강) | `2026-08-26T09:00:00Z` — #89·#105·#108·#109·#110 반영. `gh search` 로 07:00Z 이후 갱신분 전수 확인 | #74 |
| 2026-08-26 (보강) | `2026-08-26T09:11:30Z` — #110 머지·#111 리뷰·이슈 #69 반영. `decision-sweep` 스킬(#111)로 훑었다 | #74 |

번호 범위(`#1~#52` 같은)로 적으면 **이미 훑은 PR·이슈에 나중에 달린 코멘트를 못 잡는다.**
번호는 *그 항목이 존재했다*만 말하고 *그 뒤로 무슨 말이 오갔는지*는 말하지 않는다.

이번에 실제로 그랬다 — 이슈 **#37 · #41** 은 8/25 훑기 범위 안이었는데, 8/26 01:39 에 배포
형태·`data/` 마운트·자격증명 방식이 **한꺼번에 확정됐다**(7.11~7.16). "번호 #53 부터" 로만
봤으면 인프라 확정 전부를 놓쳤다.

다음 훑기는 위 시각부터 이렇게 시작한다.

```bash
gh search prs    --repo sphinx-fin/sphinx --updated ">=2026-08-26T02:02:00Z" --limit 60 \
  --json number,title,updatedAt
gh search issues --repo sphinx-fin/sphinx --updated ">=2026-08-26T02:02:00Z" --limit 60 \
  --json number,title,updatedAt
```

걸린 항목은 **번호가 낮아도 다시 열어본다.** 이 문서에 없는 것이 *결정되지 않은 것*인지
*아직 안 옮긴 것*인지는 이 표가 가른다.

## 왜 이 문서가 있나

PR 스레드에서 합의된 것이 **코드에는 반영됐지만 레포에 근거가 없는** 경우가 반복됐다. ADR
004~007 이 그중 원칙급 4건을 옮겼지만, 그건 *한 세션에서 관여한 것 위주*였고 전수가 아니었다.
이 문서가 그 전수다 — 위 표의 범위에 든 PR·이슈의 본문·리뷰·인라인 코멘트를 전부 훑었다.

**용도는 두 가지다.**

1. 코멘트를 놓친 사람이 여기 한 곳만 보면 자기 영역에서 무엇이 확정됐는지 안다
2. 다음 사람이 이미 정해진 것을 다시 정하거나 반대로 구현하는 것을 막는다

## ADR 과의 관계

| | 무엇 | 어디 |
|---|---|---|
| ADR | 원칙급 결정. 뒤집으려면 새 ADR 이 필요한 것 | `docs/adr/` |
| **이 문서** | 확정된 것 전수 색인. 세부 계약·규약·배선 결정 포함 | 여기 |

ADR 에 있는 것은 **번호만 가리키고 본문을 복제하지 않는다.** 두 벌이 되면 갈린다 —
`CanonicalJson` 이 정규화를 한 벌만 두는 것과 같은 이유다.

**이 문서는 결정을 만들지 않는다.** 전부 PR·이슈에서 이미 합의된 것이고, 출처 열이 그 근거다.
사실과 다르면 말해달라 — 남의 결정을 내가 이해한 대로 적은 것이 많다.

## 표기

- 출처 `#nn` = PR, `이슈 #nn` = 이슈
- 상태 **적용** = main 에 들어가 있음 / **계약만** = 계약은 확정, 구현·배선 남음 / **미결** = 10절
- 검증 시점: main `6325969` (#48 머지). 이후 처리된 항목은 10절에 취소선으로 표시한다
- **코드 인용은 `파일 · 심볼` 로 적고 행번호를 쓰지 않는다.** 근거로 필요한 것은 *어느 줄*이
  아니라 **그 코드가 있다**는 사실이다. 행번호는 머지마다 밀리는데 **맞는 값이 매번 바뀌므로
  대조 테스트로도 못 막는다** — 검사기를 붙이면 머지할 때마다 빨개진다. 실제로 같은 자리가
  세 번 낡았다(#74 브랜치 기준 → #123 정정 → 그 정정도 머지 전에 낡음). 심볼은 안 밀리고,
  이름이 바뀌면 그건 진짜 변경이라 로그도 같이 봐야 한다. `git grep -q '심볼' -- 파일` 한
  줄로 검사할 수 있다. 위치 자체가 필요하면 커밋 SHA 를 박은 permalink 로 고정한다
  (강희진, #123 리뷰)

| 5.16 | **집계 응답의 `synthetic` 은 설정이 아니라 상수(`true`)다** | 기획서 4절이 *"고객 실데이터는 한 건도 쓰지 않는다. 오해 지도 대시보드는 … 합성 세션으로 구성하며, 화면과 문서에 '합성 데이터'임을 표기한다"* 로 정했다. 설정으로 빼면 **끄는 것이 가능해지는데** 두 오류의 무게가 다르다 — 잘못 켜면 불필요한 워터마크(무해), 잘못 끄면 합성 수치가 실측으로 보인다(연출 금지 위반). 바꾸려면 기획을 다시 본다 | #141 | 적용 |
| 5.17 | **불공정영업 신호(`misconceptionType`)는 리포트 본문에 안 싣는다.** 역할별로 가리지 않고 **항상** 뺀다 | 그 값이 신호 그 자체다(`UnfairSalesTypes.isSignal` 이 보는 필드). 정책은 `signal:unfair:read` 를 COMPL 로 좁혔는데 리포트는 `report:read` 라 SELLER 가 자기 세션 것을 연다 — 같은 값이 다른 action 으로 새면 그 좁힘이 무의미하다(기획 7-4). **조건부로 가리면 그 부재가 곧 신호**이고, 역할마다 다른 내용을 내면 `contentHash` 가 갈려 *"고객이 받은 문서를 나중에 대조한다"* 가 성립하지 않는다. **감사는 손해 보지 않는다** — 값은 `StoredEvidenceRecorder` 가 불변 기록에 남기고 COMPL 은 `audit:read`(org)로 읽는다. 리포트는 기록이 아니라 기록에서 만든 문서다 | #145 · 이슈 #144 | 적용 |

| 5.19 | **리포트 GET·POST 를 `ReportService` 에 배선했다.** `GET` 은 발행 이력이 없으면 **404**, `POST` 는 내용이 같으면 기존 것을 돌려준다. `generatedAt` 은 **발행 기록의 시각**이지 지금 시각이 아니다 | 목이 계약보다 관대했다 — 발행 여부를 몰라 GET 이 늘 200 이었고 `contentHash` 가 `'0'*64` 였다. 계약이 GET 404 로 표현한 *"아직 교부하지 않았다"* 상태가 **존재하지 않았고**, 그 상태를 처음 만나는 시점이 배선일이면 데모 주간이다(#150 이 화면을 목에 맞추지 않은 이유의 반대편). `generatedAt` 에 `now()` 를 쓰면 **멱등이 문면만 남아** 같은 문서가 부를 때마다 다른 교부 시각을 갖는다(ADR-004) | 이슈 #54 · #156 | 적용 |

| 9.9 | **역검증이 통과하면 그 테스트는 아무것도 안 지킨다** | 고친 것을 되돌려서 테스트가 깨지는지까지 봐야 한다. 안 깨지면 셋 중 하나다 — **(1) 테스트가 파일에 안 들어갔다, (2) 들어갔지만 실행되지 않았다, (3) 실행됐지만 그 성질을 지키지 않는다.** 2026-08-26 하루에 셋 다 났다. (1) 정세현 #107 — 문자열 치환이 조용히 실패했다(`assert` 를 안 걸었다). ## 갱신 규칙

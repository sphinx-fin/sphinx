## 설계 원칙 (P1~P6) — 0.2절 전사

원본 **0.2절 「설계 원칙 (전 모듈 공통 제약)」** 을 표째 그대로 옮겼다. **해석·요약을 섞지
않았다** — 섞인 상태가 정확히 이슈 #290 이 없애려던 것이다. 우리가 붙인 것(강제 지점)은
아래에 **표를 갈라서** 뒀다. 0.4절이 「확인된 인용 + 구현 위치」로 서 있는 것과 같은 모양이다.

| # | 원칙 | 구현 제약 |
| --- | --- | --- |
| P1 | AI는 측정, 룰은 결정 | LLM 출력이 직접 게이트 판정·금액 계산에 쓰이면 안 된다. LLM 출력 → 구조화 데이터 → 룰 엔진의 단방향 흐름만 허용 |
| P2 | 숫자는 결정론 | 손실 시뮬레이션·금액 환산은 순수 함수로 구현. 동일 입력 = 동일 출력 (재현성 100%) |
| P3 | 개인정보는 LLM 이전에 제거 | PII 마스킹은 룰 기반(정규식+사전) 전처리 모듈에서 수행. LLM 프롬프트에 PII 도달 금지 |
| P4 | 판정에는 근거 첨부 의무 | 모든 채점·오해 탐지 결과는 근거 문장(고객 발화 인용 + 루브릭 조항)을 반드시 포함. 근거 없는 판정은 시스템 오류로 처리 |
| P5 | 오판 비대칭 보수 처리 | 채점 신뢰도가 임계값 미만이면 무조건 황색(재검증)으로 강등. 미탐(오해→이해 오판) 최소화가 오탐 최소화보다 우선 |
| P6 | 상품 수치는 원문 인용만 | 재설명 생성 시 상품 조건값(수익률, 배리어, 수수료 등)은 추출 원문에서 복사만 허용. LLM의 수치 생성 차단(후처리 검증) |

### 강제 지점 — 여기부터는 우리가 붙인 것이다

| | 어디가 강제하나 |
|---|---|
| **P1** | `core/gate/GateEngine` + `resources/gate_rules.yaml`(판정) ↔ `domain/Judgment`(측정값) 의 분리 |
| **P2** | `simulator/` 순수 함수 · `data/timeseries/VERSION` 스냅샷 고정 · 재현성 단위 테스트 |
| **P3** | `core/pii/PiiGateway.mask()` → `core/aiservice/AiServiceClient` 단일 경로 · ai-service 입구 재검사 |
| **P4** | `domain/Judgment` 컴팩트 생성자 · `EvidenceRequiredException` → 502 · ai-service `scoring.verify_quote_is_verbatim`·`verify_rubric_clause_is_published` |
| **P5** | `gate_rules.yaml` **R-00**(미측정이면 RED)·R-01 · `POST /judge` 판정 0건 가드([ADR-004](adr/004-evidence-append-contract.md) §6) · `eval/metrics.py` 의 `miss_rate` 를 QWK 에 접지 않는 것 |
| **P6** | `contracts/risk_item.schema.json` `condition.value_text`(*"원문 인용만 허용 (P6)"*) · `pages[page].text[start:end] == value_text` 항등식 · ai-service `reexplain` 의 환각 수치 검사 · `extraction` 의 좁히기 거부 |

❗**아직 없는 강제 지점은 없다고 적는다.** 이 파일이 *"근거처럼 생겼는데 없는 것"* 을 만들지 않으려고 한때 조항 전사를 거절했으므로(이슈 #290), 강제 지점에서도 같은 규칙을 지킨다 — P5 의 `R-00` 이 한 번 그랬고 `#291` 이 머지돼서 단서를 지웠다. 개수만 세면 안 된다: `grep -c "R-00" gate_rules.yaml` 은 그 룰이 **없을 때도 2를 셌다**(둘 다 `ADR-005` 안의 부분일치). 룰의 존재는 `grep "^\s*- id: R-00"` 로 본다.

### ❗전사하고 보니 우리 요약과 갈리는 것 셋

원본이 없는 동안 우리가 우리 말로 적어 온 것과 조항이 **정확히 같지는 않다.** 어느 쪽을
고칠지는 각 파일 소유자 몫이라 사실만 적는다.

1. **P2 의 범위가 우리 쪽이 넓다.** 우리는 *"시뮬레이터·게이트는 결정론적 순수 함수"* 로
   써 왔는데([CLAUDE.md](../CLAUDE.md) 핵심 불변식 2), 조항의 구현 제약은 **「손실
   시뮬레이션·금액 환산」** 만 든다. **게이트는 P2 조항에 안 나온다** — 게이트가 결정론인
   근거는 P1(룰 엔진 단방향)과 F-GTE-001 「제약 (P1)」 쪽이다.

2. **P5 의 「무조건」은 원본 안에서 갈린다.** 0.2절은 *"신뢰도가 임계값 미만이면 **무조건**
   황색으로 강등"* 인데, 3절 F-SCR-001 「통제 (P4, P5)」가 *"단, **U4(오해) 판정은 신뢰도가
   낮아도 강등하지 않는다** — 미탐 방지 우선"* 으로 예외를 둔다.

   **코드는 뒤쪽을 따른다.** `gate_rules.yaml` 에서 `R-01`(`anyGrade == 'U4'` → RED)이
   `R-05`(`anyConfidenceBelow 0.7` → YELLOW)보다 **앞선다** — 신뢰도가 낮은 U4 는 RED 로
   남는다. 심사에서 P5 를 근거로 들 때 0.2절만 인용하면 우리 구현이 조항 위반으로 보인다.
   **두 절을 같이 인용해야 한다.**

3. **P6 은 두 자리에서 강제된다.** 0.2절 문면은 **「재설명 생성 시」** 로 한정한다. 추출 쪽
   근거는 1절 F-EXT-002 「통제 (P6)」(*"조건값 필드는 반드시 원문 스팬을 동반. 원문에 없는
   수치가 출력되면 검증 단계에서 해당 항목 반려"*)에 따로 있다. `extraction` 의 P6 인용은
   0.2절이 아니라 그쪽을 가리키는 것으로 읽어야 맞다.

## 원본과 어긋나는 것 — F-EXT-003 기능명

원본 v1.1 과 기획서는 이 기능을 **"핵심설명서 대조"** 로 부른다. 그 문서는 **확보할 수
없다** — 공시 문서가 아니라 「보험업감독규정」§7-45 에 따라 계약 체결 권유 단계에서
계약자에게 **교부**하는 서류다(게시가 아니다).

  생명보험협회 공시실      "핵심설명서" 검색 → 0건
  삼성생명 보험상품목록    상품요약서 · 사업방법서 · 보험약관
  삼성생명 변액보험공시    변액운용설명서

그래서 이 색인은 **"공시문서 대조"** 로 적는다. 실제 정답지는 상품유형별 문서 집합이다.

  ELS   간이투자설명서
  변액  상품요약서 + 운용설명서 (어느 한쪽만으로는 이해항목 10종을 못 덮는다)

**원본이 들어와서 이 절의 전제가 확인됐다.** 추측이 아니라 실물이다 —
[`functional-spec-v1.1-original.md`](functional-spec-v1.1-original.md) 1절이 이 기능을
`F-EXT-003 추출 결과 검증 (핵심설명서 대조)` 으로 적고, 입력을 *"핵심설명서 기준 항목
세트"* 로 든다. **어긋남은 원본의 오기가 아니라 그 문서를 확보할 수 없다는 사실**이고,
그래서 이 절은 **지우지 않는다** — 원본과 이 색인이 다른 이유를 여기 말고는 적을 데가 없다.

원본 쪽을 고치는 것은 명세서 개정(v1.2)이라 별건이다. 근거는 PR #32.

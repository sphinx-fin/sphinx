# ADR-007. F-EXT-003 정답지는 상품유형별 공시문서 **집합**이다 — 핵심설명서는 확보 불가

- **상태**: Accepted
- **일자**: 2026-08-25
- **결정자**: 정세현
- **관련**: F-EXT-002, F-EXT-003, 이슈 #26, PR #32, PR #33, PR #34

## 맥락

기획서와 기능 명세서가 F-EXT-003 을 **"핵심설명서 대조"** 라 부르고, 5절이
*"핵심설명서를 정답지로 쓴다. 핵심설명서는 '고객이 반드시 알아야 할 것'을 회사가 이미
추려놓은 문서다"* 라고 못박았다.

**그 문서는 확보할 수 없다.**

「보험업감독규정」§7-45 는 상품설명서와 변액보험 운용설명서를 **계약 체결 권유 단계에서
계약자에게 교부**하도록 한다. 게시가 아니라 교부다. 실제 계약을 하지 않는 한 손에 넣을 방법이
없다.

| 확인한 곳 | 제공 문서 |
|---|---|
| 생명보험협회 공시실 | "핵심설명서" 검색 → **0건** |
| 삼성생명 보험상품목록 | 상품요약서 · 사업방법서 · 보험약관 |
| 삼성생명 변액보험 상품공시 | **변액운용설명서** |

기획서 218행이 *"각 보험사 상품공시실 : 약관, 상품요약서, 사업방법서, 그리고 권유 단계의
상품설명서와 핵심설명서"* 라고 쓴 것이 **사실과 다르다.** 앞의 셋은 공시되지만 뒤의 둘은 아니다.

## 결정

### 1. 정답지는 단일 문서가 아니라 상품유형별 **집합**이다

```
ELS    간이투자설명서
변액   상품요약서 + 운용설명서
```

### 2. 변액은 두 문서의 합집합이어야 한다

운용설명서를 확보해 `data/documents/` 에 넣었다(PR #32). 그런데 **이해항목 10종 중 6종만
덮는다.**

| | 운용설명서 | 상품요약서 |
|---|---|---|
| 실적배당형 · 원금손실 · 예금자보호 · 계약체결관리비용 · 저축과 다름 · 최저보증 부재 | ✅ | ✅ |
| 월공제액 · 중도인출 수수료 · 환급률 58.4%(3개월) · 43.9%(20년) | ❌ | ✅ (p10·p12) |

운용설명서는 펀드 운용·보증비용 중심이라 사업비 수치가 없다. **어느 한쪽을 정답지로 고르면
그 순간 4종 또는 6종이 구조적으로 못 맞히는 항목이 된다** — 이슈 #26 이 루브릭 레벨에서 지적한
문제가 문서 레벨에서 다시 나는 셈이다.

### 3. 기능명을 "공시문서 대조"로 바꾼다

없는 문서를 가리키는 기능명으로는 정답 세트를 확정할 수 없다. `functional-spec-v1.1.md:33` ·
`role-assignment-v1.2.md:20-21` 을 고쳤다(PR #33).

### 4. 기획서 문면도 고쳤다 — `proposal.md` 가 정본이다

218 · 231 · 232 · 239행을 공시문서 기준으로 정정했다(PR #34).

그 과정에서 문서 운영 방향이 거꾸로 적혀 있던 것도 바로잡았다. `proposal.md` 헤더와
`docs/README.md` 가 이 파일을 *"원본 PDF 의 전사본, 문면 수정 금지"* 라 규정했는데, 실제
운영은 반대다 — **이 파일이 정본이고 제출용 PDF 를 여기서 뽑는다.** 그 잘못된 전제 때문에
PR #23 이 7-2 표 수정을 되돌린 적이 있다.

## 부수 발견 — `VAR-NO-DEPOSIT-INSURANCE` 항목 정의가 틀렸다

운용설명서 p1 이 이렇다.

> 이 보험계약은 약관에서 정한 최저사망지급금, 최저실적배당종신연금 및 특약에 **한하여**
> 예금자보호법에 따라 보호됩니다. 보호 한도는 … 1인당 "1억원까지"

우리는 이 항목을 "예금자보호 **비대상**"으로 뒀는데 실제는 **부분 보호**다. 정답 세트 확정 전에
항목 정의를 고쳐야 하고, 루브릭 `required_elements` 도 "보호되지 않는다"가 아니라 **"어디까지
보호되는가"** 를 요구해야 한다. 오히려 채점 난도가 올라간다.

## 남은 의존

정답 세트의 **분모**(23종 전부 / `importance: required` 만 / 데모 경로만)는 이슈 #26 에서
미결이다. 이 ADR 은 "어느 문서를 근거로 삼는가"까지만 정한다.

## 결과

- "핵심설명서를 정답지로 쓴다"는 기획서 문장은 지킬 수 없고, 그 사실이 문서에 남았다.
- 변액 파서 입력이 2종(`var_samsung_b2601_product_summary.pdf`,
  `var_samsung_b2601_operations_manual.pdf`)이 됐다. 운용설명서는 안정적인 직접 URL 이 있어
  `fetch_documents.py` 가 자동 수집한다 — 변액 문서 중 처음이다.
- `scripts/make_parsing_samples.py` 가 아직 2종만 만든다. 3종으로 늘릴지는 분모 확정 후에 정한다.

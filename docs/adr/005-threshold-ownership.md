# ADR-005. 판정을 바꾸는 임계값은 게이트가 소유하고, 측정 자신감은 ai-service 가 소유한다

- **상태**: Accepted
- **일자**: 2026-08-24
- **결정자**: 강희진 / 제안: 윤지석 / 협의: 정세현
- **관련**: P1, F-SCR-001, F-GTE-001, F-DET-002, PR #10, PR #15

## 맥락

F-SCR-001 채점 구현 초안이 신뢰도 기반 황색 강등을 **ai-service 안에서** 처리했다 —
`confidence < 0.7` 이면 자기가 내는 `grade` 를 U1 → U2 로 바꿔 내보내고, 게이트의 R-04 가
U2 를 YELLOW 로 받는 구조였다.

동작은 했지만 두 문제가 있었다.

1. **P1 위반.** *"AI는 측정, 룰은 결정"* 인데 게이트 정책(어느 신뢰도부터 통과시키지 않을지)이
   채점 쪽에 들어가 있었다
2. **같은 임계값 0.7 이 두 곳에 살았다.** `application.yml` 의
   `sphinx.scoring.confidence-threshold`(선언만 되고 소비자 없음)와 ai-service 의 Python 상수

그런데 F-DET-002(적합성 모순)에서는 반대 결론이 났다 — 모순 탐지의 `confidence` 임계값은
ai-service 에 남긴다. 두 경우를 가르는 기준이 필요했다.

## 결정

### 채점 임계값은 게이트로 이관한다

ai-service 는 **모델이 낸 grade 와 confidence 를 그대로** 내보낸다. 강등은
`gate_rules.yaml` 이 한다.

```yaml
R-01  anyGrade == 'U4'         → RED
R-04  anyGrade in ['U2','U3']  → YELLOW
R-05  anyConfidenceBelow 0.7   → YELLOW
R-06  allGrade == 'U1'         → GREEN
```

`downgrade_low_confidence()` 와 `CONFIDENCE_FLOOR` 를 제거했다. 임계값의 단일 출처가
`gate_rules.yaml` 이 됐다.

**U4 예외를 따로 코딩하지 않는다.** first-match-wins 이므로 R-01 이 먼저 잡는다. 룰 순서가
그 예외를 이미 표현한다.

### 가르는 기준 — "판정을 바꾸는가" vs "측정의 자신감인가"

| | 성격 | 소유 |
|---|---|---|
| 채점 임계값 | grade 를 바꿔 **게이트 입력을 흔든다** | 게이트 정책 (`gate_rules.yaml`) |
| 모순 임계값 | "우리가 모순을 봤다고 말할 만한가" | 탐지 자신감 = 측정 (ai-service) |

F-DET-002 는 `mismatch: bool` + `confidence: number` 를 내보내고, 취약 가중·코칭 스코어는
서버가 `vulnerability_weights.yaml` 로 산출한다. 즉 **판정=ai-service / 가중·코칭=서버**다.

새 임계값이 생길 때 이 표로 판단한다.

## 관측된 한계 (구현 전 참고)

`gemini-3.5-flash-lite` 에 애매한 발화를 넣어도 confidence 가 0.80 아래로 내려오지 않는다.

| 발화 | 등급 | conf |
|---|---|---|
| "잘 모르겠어요." | U3 | 1.00 |
| "뭐 떨어지면 좀 손해가 나는 거 아닌가요." | U2 | 0.80 |

모델이 *등급 배정에 대한 확신*을 보고하고, 모호성은 등급 자체를 낮추는 방식으로 표현한다.
게다가 R-05 가 실제로 판정을 바꾸는 경우는 **전부 U1 인 세션 하나뿐**이다 — 낮은 신뢰도의
U2·U3 는 R-04 가, U4 는 R-01 이 이미 잡는다.

**즉 현재 프롬프트에서 R-05 는 거의 발동하지 않는다.** 프롬프트 v2 에서 confidence 정의를
"등급 확신도"에서 "발화의 모호성"으로 바꿔 재측정할 예정이며, 그때 이 임계값을 다시 본다.
결정 자체(소유 경계)는 그 결과와 무관하다.

## 결과

- 임계값이 `gate_rules.yaml` 한 곳에 있어 변경이 PR 로 남는다(감사 대상).
- 이중 계산이 없다. ai-service 가 강등하고 게이트가 또 강등하는 경로가 사라졌다.
- `ruleTrace` 관측 참고: R-05 가 R-04 뒤에 있어 신호는 같지만 트레이스에는 먼저 발화한 룰만
  남는다. U2 가 있고 동시에 신뢰도도 낮은 세션은 R-04 만 기록되고 신뢰도 문제가 보이지 않는다.
  판정은 같으므로 문제는 아니고, 감사 기록에서 두 사유를 구분하고 싶을 때 볼 지점이다.

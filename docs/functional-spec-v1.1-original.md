| 항목 | 내용 |
| --- | --- |
| 문서 버전 | v1.1 (2026-08-22) — 음성 입력 제외, 텍스트 전용으로 확정 |

## 0. 시스템 개요

### 0.1 한 줄 정의

금융상품 계약 직전, 고객이 상품을 자기 말로 설명하게 하고(되말하기), AI가 항목별 이해도를 채점하여, 룰 엔진이 판매 진행 여부를 신호등으로 판정하는 이해도 검증 게이트.

### 0.2 설계 원칙 (전 모듈 공통 제약)

| # | 원칙 | 구현 제약 |
| --- | --- | --- |
| P1 | AI는 측정, 룰은 결정 | LLM 출력이 직접 게이트 판정·금액 계산에 쓰이면 안 된다. LLM 출력 → 구조화 데이터 → 룰 엔진의 단방향 흐름만 허용 |
| P2 | 숫자는 결정론 | 손실 시뮬레이션·금액 환산은 순수 함수로 구현. 동일 입력 = 동일 출력 (재현성 100%) |
| P3 | 개인정보는 LLM 이전에 제거 | PII 마스킹은 룰 기반(정규식+사전) 전처리 모듈에서 수행. LLM 프롬프트에 PII 도달 금지 |
| P4 | 판정에는 근거 첨부 의무 | 모든 채점·오해 탐지 결과는 근거 문장(고객 발화 인용 + 루브릭 조항)을 반드시 포함. 근거 없는 판정은 시스템 오류로 처리 |
| P5 | 오판 비대칭 보수 처리 | 채점 신뢰도가 임계값 미만이면 무조건 황색(재검증)으로 강등. 미탐(오해→이해 오판) 최소화가 오탐 최소화보다 우선 |
| P6 | 상품 수치는 원문 인용만 | 재설명 생성 시 상품 조건값(수익률, 배리어, 수수료 등)은 추출 원문에서 복사만 허용. LLM의 수치 생성 차단(후처리 검증) |

### 0.3 시스템 구성도

```
[상품문서 PDF] ─→ (M1) 위험요소 추출 엔진 ─→ 필수이해항목 DB
                                                    │
[고객/판매자 태블릿·앱] ⇄ (M2) 되말하기 인터뷰 엔진 ←┘
        │                        │
        │                 (M3) 채점·오해·모순 탐지
        │                        │
        ├──── (M4) 손실 시뮬레이터 (결정론)
        │                        │
        └──── (M5) 판매 게이트(룰 엔진) + 이해 기록 리포트
                                 │
                    (M6) 오해 지도 대시보드 (익명 집계)
```

### 0.4 사용자 역할

| 역할 | 코드 | 권한 |
| --- | --- | --- |
| 고객 | CUST | 인터뷰 응답, 시뮬레이터 조작, 본인 이해 기록 열람 |
| 판매 직원 | SELLER | 세션 시작/종료, 판정 결과 열람(근거 포함), 재설명 실행 |
| 관리자(지점) | MGR | 적색 세션 승인/반려 + 사유 기록 |
| 컴플라이언스 | COMPL | 전체 세션 조회, 불공정영업 알림 수신, 대시보드, 감사 로그 |
| 시스템 관리자 | ADMIN | 루브릭·오해 라이브러리·템플릿 관리, 접근 권한 관리 |

※ 영업(마케팅) 조직 역할은 존재하지 않는다. 이해도 데이터 접근 권한을 부여할 수 있는 역할 자체를 만들지 않는 것이 역이용 방지 요건(기획서 7-1)의 구현이다.

### 0.5 핵심 상태 정의

**이해도 4단계 (항목 단위)**

| 코드 | 명칭 | 정의 | 게이트 매핑 |
| --- | --- | --- | --- |
| U1 | 이해 | 루브릭 필수 요소를 자기 말로 재현 | 녹색 |
| U2 | 부분이해 | 필수 요소 일부 누락, 오류는 없음 | 황색 |
| U3 | 미이해 | "모르겠다" 또는 무관한 답변 | 황색 |
| U4 | 오해 | 사실과 다른 내용을 사실로 진술 | 적색 |

**신호등 3색 (세션 단위, 룰 엔진 산출)**

| 코드 | 조건(기본 룰) | 후속 동작 |
| --- | --- | --- |
| GREEN | 전 항목 U1 | 판매 진행 가능, 이해 기록 확정 |
| YELLOW | U2/U3 존재, U4 없음 | 해당 항목만 재설명 → 재검증 루프 |
| RED | U4 1건 이상 또는 적합성 모순 탐지 또는 재검증 2회 실패 | 판매 보류 권고, 진행 시 MGR 승인+사유 필수 |

## 1. M1. 위험요소 자동 추출 엔진

### F-EXT-001 상품문서 업로드 및 파싱

| 항목 | 내용 |
| --- | --- |
| 설명 | 간이투자설명서(ELS)·상품요약서/핵심설명서(변액보험) PDF를 업로드받아 텍스트·표를 구조화한다 |
| 입력 | PDF 파일 (≤30MB), 상품유형 선택(ELS / 변액보험) |
| 출력 | 문서 파싱 결과 JSON (섹션 트리, 표 데이터, 페이지·좌표 참조) |
| 처리 | ① 텍스트 레이어 추출 → ② 텍스트 레이어 부재 시 OCR 폴백 → ③ 표 구조 복원 → ④ 섹션 분할 |
| 예외 | E-EXT-01 암호화 PDF: 업로드 거부, 안내 메시지 / E-EXT-02 OCR 신뢰도 < 90%: "수동 확인 필요" 플래그 |
| 수용 기준 | 데모용 대상 문서 2종(ELS 1, 변액 1)에서 필수 조건 항목이 위치 참조와 함께 파싱됨 |

### F-EXT-002 필수 이해항목 추출 (LLM)

| 항목 | 내용 |
| --- | --- |
| 설명 | 파싱된 문서에서 상품유형별 템플릿에 정의된 필수 이해항목과 조건값을 추출·구조화한다 |
| 입력 | 파싱 결과 JSON, 상품유형 템플릿 |
| 출력 | `RiskItem[]` — {항목ID, 항목명, 조건값(원문 인용+페이지 참조), 중요도(필수/권장)} |
| 상품유형 템플릿 (MVP 고정) | **ELS**: 원금손실 조건(낙인 배리어), 기초자산, 조기상환 구조, 예금자보호 비대상, 최대 손실률, 만기/상환 조건 · **변액/갱신 보험**: 원금손실 가능성, 사업비 차감 구조, 해지환급금 < 납입액 구간, 갱신 보험료 인상, 최저보증 조건 |
| 통제 (P6) | 조건값 필드는 반드시 원문 스팬(문서 내 시작·끝 오프셋)을 동반. 원문에 없는 수치가 출력되면 검증 단계에서 해당 항목 반려 |
| 예외 | E-EXT-03 템플릿 필수 항목 미발견: 항목을 비우지 않고 "추출 실패" 상태로 생성 → 사람 확인 큐로 이동 (누락 은폐 금지) |
| 수용 기준 | 핵심설명서 대비 필수 항목 재현율 측정 리포트 산출 가능. 누락 항목은 반드시 "추출 실패"로 가시화 |

### F-EXT-003 추출 결과 검증 (핵심설명서 대조)

| 항목 | 내용 |
| --- | --- |
| 설명 | 자동 추출 항목을 핵심설명서(정답 레이블)와 대조해 정확도를 정량 산출한다 |
| 입력 | RiskItem[], 핵심설명서 기준 항목 세트 |
| 출력 | 검증 리포트 {재현율, 정밀도, 불일치 목록} |
| 용도 | MVP 성능 증빙 + ADMIN의 템플릿 개선 루프 |

## 2. M2. 되말하기 인터뷰 엔진

### F-INT-001 검증 세션 생성

| 항목 | 내용 |
| --- | --- |
| 설명 | 상품·고객 속성·채널을 바인딩한 검증 세션을 생성한다 |
| 입력 | 상품ID, 채널(창구 태블릿/모바일), 고객 속성 {연령대(10세 구간), 투자경험 수준(3단계), 투자성향 설문 결과, 가입 예정 금액구간}, 판매자ID(창구인 경우) |
| 출력 | 세션ID, 검증 대상 항목 목록(RiskItem 기반) |
| 제약 (P3) | 고객 성명·주민번호·계좌번호는 입력 스키마에 존재하지 않는다. 세션은 금융사 측 계약건 참조번호로만 연결 |
| 상태 머신 | CREATED → IN_PROGRESS → (RE_EXPLAIN ⇄ RE_VERIFY)* → JUDGED → CLOSED / ABORTED |

### F-INT-002 되말하기 질문 생성 (LLM)

| 항목 | 내용 |
| --- | --- |
| 설명 | 항목별 되말하기 질문을 자동 생성한다 |
| 입력 | RiskItem, 고객 연령대·경험 수준 |
| 출력 | 질문 텍스트 (항목당 1개, 재검증 시 변형 질문 1개 추가) |
| 통제 | 질문 유형 화이트리스트만 허용: ①상황 설명형("~한 상황을 본인 말씀으로 설명해 주세요") ②금액 환산형 ③조건 재현형. 질문 문면에 정답 요소 노출 금지 — 생성 후 정답 키워드 포함 여부를 후처리 검사, 걸리면 재생성 |
| 예외 | E-INT-01 3회 재생성 실패: 항목별 사전 작성 기본 질문(fallback)으로 대체 |

### F-INT-003 응답 수집 (텍스트)

| 항목 | 내용 |
| --- | --- |
| 설명 | 고객 응답을 텍스트로 수집한다 (음성 입력은 MVP 범위 외 — §11 확장 목록) |
| 입력 | 텍스트 (자유 서술형) |
| 출력 | 응답 텍스트 + 메타데이터 {입력 시작까지 지연시간(ms), 총 입력 시간, 응답 길이, 붙여넣기 이벤트 여부, 수정(백스페이스) 빈도} |
| 처리 | 텍스트 입력 → PII 패턴 실시간 마스킹(전화번호·주민번호 패턴 등) → 응답 확정 |
| 예외 | E-INT-02 극단적 단답(공백 제외 5자 미만): "조금 더 자세히 적어 주세요" 1회 재요청 / E-INT-03 무응답 60초: 안내 후 항목 건너뛰기(U3 처리) 확인 |
| 메모 | 입력 지연·붙여넣기·정형성 메타데이터는 F-DET-002(코칭 탐지)의 입력이 된다. 창구 채널에서 고령 고객은 타이핑 부담이 크므로, 판매자가 아닌 고객 본인이 입력했음을 확인하는 화면 안내를 포함한다(대필 방지) |

### F-INT-004 재설명 생성 및 재검증 루프

| 항목 | 내용 |
| --- | --- |
| 설명 | U2~U4 판정 항목에 대해 맞춤 재설명을 생성·제시하고, 변형 질문으로 재검증한다 |
| 입력 | 판정 결과(오해 유형 포함), 고객 연령대·경험 |
| 출력 | 재설명 콘텐츠 (텍스트, 고령자 모드: 짧은 문장·비유·큰 글씨·숫자의 시각화) |
| 통제 (P6) | 재설명 내 상품 수치는 RiskItem 원문 인용만. 생성 후 수치 대조 검증 필수 |
| 루프 제한 | 항목당 재검증 최대 2회. 2회 실패 시 해당 항목 최종 상태 확정 후 게이트로 이관 (무한 루프 금지) |
| 수용 기준 | 전체 세션(항목 5~7개, 재설명 1~2회 포함) 7분 이내 — 사용성 테스트로 측정 |

## 3. M3. 채점·오해·모순 탐지

### F-SCR-001 항목별 이해도 채점 (LLM)

| 항목 | 내용 |
| --- | --- |
| 설명 | 고객 발화를 항목별 루브릭에 대입해 U1~U4로 판정한다 |
| 입력 | 발화 전사, 항목 루브릭 {필수 요소 목록, 오해 판정 조건}, RiskItem 조건값 |
| 출력 | `Judgment` — {항목ID, 등급(U1~U4), 신뢰도 점수, 근거: {인용 발화 스팬, 매칭된 루브릭 조항}, 판정 사유 1문장} |
| 통제 (P4, P5) | 근거 스팬 누락 시 판정 무효 → 재판정 1회 → 실패 시 U2(황색)로 보수 확정. 신뢰도 < 임계값(초기 0.7)이면 등급과 무관하게 황색 강등. 단, **U4(오해) 판정은 신뢰도가 낮아도 강등하지 않는다** — 미탐 방지 우선 |
| 성능 관리 | 사람 채점 대비 일치율(가중 카파) 측정 파이프라인 내장. 오해→이해 오판율(미탐)을 별도 지표로 추적 |
| 예외 | E-SCR-01 LLM 타임아웃(8초): 1회 재시도 → 실패 시 해당 항목 "판정 불가"(황색 취급) + SELLER 알림 |

### F-DET-001 오해 탐지 (라이브러리 + 의미 유사도)

| 항목 | 내용 |
| --- | --- |
| 설명 | 발화를 사전 구축된 오해 패턴 라이브러리와 대조해, 표현이 달라도 같은 오해를 식별한다 |
| 입력 | 발화 전사, 오해 패턴 라이브러리(분쟁조정례·검사결과 기반 유형화, 버전 관리) |
| 출력 | 매칭된 오해 유형 {유형ID, 대표 패턴, 유사도 점수, 발화 인용} |
| MVP 라이브러리 (초기 탑재 8종) | ① 원금보장 오인("은행이 파니까 안전") ② 예금자보호 오인 ③ 확률 오인("반토막 날 리 없다") ④ 조기상환 구조 오인("만기에 원금+이자") ⑤ 저축성 오인(변액) ⑥ 해지환급금 오인("낸 돈은 다 돌려받는다") ⑦ 수익률 과신(제시 수익률=확정 수익) ⑧ 꺾기 신호("대출받으려면 들어야 한다") |
| 특수 처리 | 유형⑧(꺾기)은 이해도 판정과 무관하게 **불공정영업 신호 이벤트**를 즉시 발행 → COMPL 알림 (F-GTE-003 연동) |
| 통제 | 라이브러리 매칭이 1차 판정(재현성 담보), LLM 유사도는 변형 표현 커버용 2차. 라이브러리 외 신규 오해는 "미분류 오해 후보"로 큐 적재 → ADMIN 검토 후 라이브러리 편입 |

## 7. 공통 기능

### F-CMN-001 PII 마스킹 전처리

룰 기반(정규식+성명 사전+체크섬 검증: 주민번호·계좌번호·전화번호·주소). LLM 호출 게이트웨이 직전에 강제 배치되는 미들웨어로 구현 — 어떤 모듈도 이 게이트웨이를 우회해 LLM을 호출할 수 없다(네트워크 정책으로 차단). 마스킹 실패 감지 시 해당 요청 폐기 + 관리자 알림.

### F-CMN-002 접근 통제·감사 로그

역할 기반 접근 통제(0.4절), 전 데이터 접근의 감사 로그(불변 저장), 이해도 데이터에 대한 영업 조직 접근 경로 부재를 아키텍처로 보장.

### F-CMN-003 채점 성능 측정 파이프라인

사람 채점 세트(항목당 최소 30발화, 팀 교차 채점) 대비: 가중 카파, 등급별 혼동 행렬, **미탐율(U4→U1/U2 오판)** 별도 산출. 리포트는 데모·심사 제출물에 첨부.

## 9. API 초안

```
POST   /products/documents              # 문서 업로드 (F-EXT-001)
POST   /products/{id}/extract           # 위험요소 추출 실행 (F-EXT-002)
GET    /products/{id}/risk-items
POST   /sessions                        # 세션 생성 (F-INT-001)
POST   /sessions/{id}/questions/next    # 다음 질문 (F-INT-002)
POST   /sessions/{id}/answers           # 응답 제출(텍스트) (F-INT-003) → 채점 결과 반환
POST   /sessions/{id}/re-explain        # 재설명 요청 (F-INT-004)
POST   /sessions/{id}/simulate          # 손실 계산 (F-SIM-001)
POST   /sessions/{id}/judge             # 게이트 판정 (F-GTE-001)
POST   /sessions/{id}/override          # 적색 진행 요청 (F-GTE-002)
POST   /sessions/{id}/override/approve  # MGR 승인/반려
GET    /sessions/{id}/report            # 이해 기록 (F-GTE-004)
GET    /dashboard/heatmap               # 오해 지도 (F-DSH-001)
```

모든 세션 API는 판정 근거(evidence) 필드를 응답에 포함한다 (P4).

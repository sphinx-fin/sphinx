# 평가 표본 (F-CMN-003)

소유: 정세현. 라벨은 여기 **없다** — 강희진·오준서가 `eval/data/labels/` 에 따로 붙인다.

```
els.jsonl   ELS 10개 이해항목 × 4 = 40건
```

한 줄이 한 `(발화, 항목)` 이다. 라벨러가 보는 것이 이 네 필드 전부다.

```json
{"sample_id":"els-0001","product_type":"ELS","item_id":"ELS-PRINCIPAL-LOSS-WARNING","utterance":"제가 넣은 돈이 …"}
```

## ❗등급이 없는 것은 빠뜨린 것이 아니다

표본을 만든 사람(운영자)은 **라벨링에서 빠진다**(`eval/README.md` · 역할표 F-EXT-003
*"평가자와 피평가자를 분리"*). 그런데 표본 파일에 "내가 의도한 등급"을 적어 두면 그게 곧
정답 라벨이고, 분리는 이름만 남는다. 그래서 **의도 등급을 어디에도 기록하지 않았다** —
별도 파일에도 두지 않았다. 나중에 누가 그걸 gold 로 착각할 여지를 안 만든다.

`test_corpus.py` 가 `grade`·`gold`·`label`·`expected` 키가 하나라도 있으면 실패시킨다.

균형은 **구성으로** 맞췄다. 항목마다 네 발화를 두되 이해 쪽·부분·비답변·오해 쪽이 고루
섞이도록 썼다. 실제로 그렇게 됐는지는 두 사람의 라벨 분포가 말해 준다 — 치우쳤으면
`run_eval.py` 가 등급 분포를 찍고, 합의 표본에 U4 가 없으면 경고한다.

## ❗오해 라이브러리 `patterns` 를 베끼지 않는다

`apply_misconception_floor` 가 라이브러리 패턴에 **문자열로** 걸리면 `stage=pattern 1.000`
으로 U4 를 확정한다. 같은 문자열을 표본에 넣으면 **학습 데이터로 시험하는 것**이 된다 —
점수는 올라가고 일반화는 하나도 안 재게 된다.

그래서 같은 오해를 **다른 말로** 쓴다. 그게 이 표본이 실제로 재려는 것이다.

```
라이브러리 패턴   "은행에서 파니까 원금은 보장"
표본             "그래도 은행 창구에서 파는 건데, 최소한 넣은 돈은 지켜 주는 거 아닌가요?"
```

`test_corpus.py` 가 11개 패턴 전부와 대조한다. **패턴을 0개 뽑으면 실패시키는 단정이 먼저
있다** — 라이브러리 형식이 바뀌어 추출이 비면 대조가 아무것도 안 재면서 초록이 된다.

> 처음엔 이 추출을 정규식으로 짰다가 `source.quote`·`id:` 줄·**주석 본문**까지 38개를
> 긁었다. 하필 *"조각을 패턴으로 두면 정답 발화도 잡는다"* 고 경고하는 주석에서
> `중간에 빼면` 을 뽑아, 그 조각을 담은 **정답 발화**를 위반으로 신고했다. 라이브러리가
> 패턴을 문장 전체로 두는 이유(M04 선례)와 같은 함정이라 파서로 바꿨다.

## 발화는 내가 썼다 — 그 사실이 리포트에 남아야 한다

공개된 실제 상담 녹취가 없어서 **운영자가 창작했다.** 기준은 루브릭
(`ai-service/app/rubrics/ELS-*.yaml`)의 `required_elements`·`misconception_conditions` 이고,
라이브러리 패턴이 아니다 — 매칭 엔진이 이미 아는 문자열을 피하려는 것이다.

이게 남기는 한계는 둘이고, 성능 리포트에 그대로 적어야 한다.

1. **난이도를 만든 사람이 정했다.** 실제 창구 발화보다 쉬울 수도 어려울 수도 있다
2. **프롬프트 당사자(윤지석)가 아니라는 것까지만 보장된다.** 채점기를 만든 사람과
   시험지를 만든 사람은 다르지만, 시험지와 채점 기준(루브릭)의 출처는 같다

1번을 줄이려면 실제 분쟁조정례(`data/dispute_cases/`)의 고객 진술을 인용하는 쪽이 낫다.
PDF 두 건이 있으니 다음 판에서 대조해 볼 자리다.

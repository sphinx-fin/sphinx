# eval (운영: 정세현 / 라벨러: 정세현·강희진 — 2인, ❗독립 조건은 guideline.md §5)

F-CMN-003 채점 성능 평가 파이프라인.

- 목표: 가중 카파(QWK) 0.75+, 오해→이해 오판(미탐) 별도 관리
- 절차: 평가 표본 → 정세현·강희진 2인 라벨 → 평가자 간 일치도 → 모델 vs 사람 일치도 산출
- 윤지석(프롬프트 당사자)은 라벨링 제외
- ❗**정세현이 라벨러이자 운영자다**(2026-09-03 운영자 결정). 평가자·피평가자 분리가
  완전하지 않으므로 **1번 수치를 조건 없이 「상한」으로 인용하지 않는다** — 무엇이 얼마나
  약해지는지는 `eval/labeling/guideline.md` §5 에 있다

```
metrics.py             QWK · 혼동행렬 · 미탐율 · 일치율 — 순수 함수, 의존성 없음
run_eval.py            입력을 읽어 리포트를 낸다. 입력이 없으면 비영점으로 죽는다
labeling/guideline.md  두 라벨러가 같은 발화에 같은 등급을 붙이게 하는 규칙
tests/                 손으로 검산 가능한 예제로 지표를 고정한다
```

## 돌리기

```bash
python eval/run_eval.py                  # 리포트를 stdout 으로
python eval/run_eval.py --out report.md  # 파일로도
```

읽는 파일 — 한 줄이 한 `(표본, 항목)` 이다.

```
eval/data/model.jsonl          {"sample_id": …, "item_id": …, "grade": "U4"}
eval/data/labels/강희진.jsonl   같은 모양
eval/data/labels/정세현.jsonl   같은 모양
```

## ❗숫자를 지어내지 않는다

이 파이프라인의 설계 원칙 하나다. 입력이 없거나, 라벨러가 한 명이거나, 표본이 30건 미만
이거나, 두 채점 결과가 한 등급뿐이면 **그 값을 안 찍고 이유를 적는다.** 0.0 을 찍으면
"평가했더니 0.0 이었다"로 읽히는데 실제로는 평가를 안 한 것이라, 리포트 문면만으로는
둘이 구별되지 않는다.

- 라벨 파일 2개 미만 → 거부. 평가자 간 일치도가 **상한**이라, 상한 없이는 모델 점수가
  좋은지 나쁜지 말할 수 없다
- 표본 30건 미만 → 카파를 안 찍는다. 항목 하나가 소수점 둘째 자리를 흔들어서 회차 비교가
  무의미해지는데 숫자는 그대로 그럴듯하다
- 합의 표본에 U4 가 0건 → 미탐율 대신 경고. 게이트의 핵심 실패 모드를 아예 못 잰 회차다

## ❗미탐율을 카파에 접지 않는다

`U4`(오해)를 `U1`·`U2`로 읽는 것은 게이트가 위험을 그냥 통과시키는 경우다. 표본에서 U4 가
소수면 **카파가 목표선 근처인데 미탐율이 나쁠 수 있다** — `tests/test_metrics.py` 가 QWK
0.73 · 미탐 30% 인 표본으로 그 상태를 고정한다. 숫자 하나로 합치면 그게 안 보인다.

## 아직 없는 것 — 사람 라벨

`eval/data/labels/` 가 비어 있다. 표본 70건(`eval/corpus/els.jsonl`)과 모델 등급 70건
(`eval/data/model.jsonl`)은 다 있고, **두 사람의 라벨만 들어오면 리포트가 나온다.**

라벨러는 `eval/labeling/worksheet.html` 을 브라우저로 열어 붙인다 — 그 파일 하나면 되고
`eval/data/` 를 지나지 않는다(거기 model.jsonl 이 있어서 그렇다).

**합성 세션(`data/synth_sessions/`)은 재료가 못 된다** — 등급 분포만 있고 발화가 없어서
(대시보드 집계용 생성물), 채점을 라벨링할 대상이 아니다.

# 순찰

열린 PR 과 이슈에서 **지금 내 손에 있는 것**을 찾아 처리한다. 한 번 도는 것이 한 사이클이고,
`/loop` 로 주기 실행하면 매번 이 절차를 다시 탄다.

## 규칙은 여기 적지 않는다

PR 을 어떻게 내고 누가 리뷰하는지는 **이미 문서에 있다.**

| 규칙 | 어디 |
|---|---|
| 파일·디렉토리 소유자 · 브랜치 이름 | `CLAUDE.md` → `## 소유권과 기여 규칙`, `docs/role-assignment-v1.2.md` |
| 리뷰 라벨은 자동이다 · 가드의 빨강 두 가지 | `CLAUDE.md` → `### PR 리뷰 라벨은 자동이다` |
| 계약 변경 승인 · 핵심 불변식 P1~P4 | `CLAUDE.md` → `## 아키텍처`, `contracts/` |
| 결정을 문서로 옮기는 절차 | `.claude/skills/decision-sweep/` |

**여기에 옮겨 적지 말 것.** 두 벌이 되면 갈리고, 갈린 걸 아무도 모른다.
이 파일에는 **순찰에서만 생기는 판단**만 둔다.

## 절차

### 1. 현황을 뽑는다

```bash
.claude/skills/patrol/scan.sh          # 전체
.claude/skills/patrol/scan.sh inbox    # 내 차례인 것만
```

판단은 하지 않고 늘어놓기만 한다. 갈라내는 것은 다음 단계다.

### 2. 다섯 갈래로 가른다

| 갈래 | 신호 | 할 일 |
|---|---|---|
| **머지할 것** | **내 PR** 이고 라벨이 없다(전원 승인) | 아래 「머지」 대로 넣는다 |
| **답할 것** | 내 PR·이슈인데 **마지막 발언이 남**이다 | 읽고 답한다. 변경요청이면 고쳐서 푸시하고 무엇을 고쳤는지 적는다 |
| **리뷰할 것** | 내게 리뷰 요청이 왔다 · 내가 변경요청한 PR 이 고쳐졌다 | 아래 「리뷰」 대로 본다 |
| **작업할 것** | 내가 맡은 이슈 · 임자 없는데 내 영역인 이슈 | 브랜치를 따고 PR 까지 끌고 간다 |
| **건드리지 않을 것** | 남의 PR · 남의 영역 이슈 | 초록이어도 머지하지 않는다. 알려만 준다 |

**마지막 발언이 나인 것은 기다리는 중이다 — 다시 재촉하지 않는다.**
한 스레드에 재촉이 두 번 넘게 쌓였으면 세 번째를 쓰지 말고 사용자에게 보고한다.
예외는 **새 사실이 생겼을 때**다(다른 리뷰어가 승인했다 · 막고 있던 PR 이 머지됐다).
그때는 재촉이 아니라 그 사실만 짧게 적는다.

### 3. 한 사이클에 하나를 끝까지 끌고 간다

여러 건을 동시에 벌이지 않는다. 고르는 순서는 이렇다.

```
1. 머지 조건을 갖춘 내 PR      — 끝난 일이다. 두면 base 가 낡고 「합친 결과」 위험만 는다
2. 답이 밀린 스레드           — 남이 내 답을 기다리는 중이다. 제일 비싸다
3. 내게 온 리뷰 요청          — 남의 작업이 내 손에서 멈춰 있다
4. 내 PR 의 빨강              — 내 것이 막혀 있다
5. 내가 맡은 이슈             — 데모 경로·보안 라벨이 붙은 것부터
6. 임자 없는 내 영역 이슈      — 가져올 때 assignee 를 같이 붙인다
```

**머지는 한 사이클에 하나가 아니다** — 조건을 갖춘 것은 전부 넣는다. 아래 넷과 달리
판단이 끝난 일이라 나눠 쌓을 이유가 없다.

### 4. 주장마다 실측을 붙인다

이 레포는 **요약만으로는 리뷰가 안 통과한다.** 이슈가 무엇을 주장하든 그대로 받지 말고
해당 줄을 열어 재현하고, 재현한 것을 PR 본문에 줄 번호와 같이 적는다.

**고친 뒤에는 변이 역검증을 한다** — 고친 한 줄을 되돌리고 테스트를 돌려서 **빨개지는지**
본다. 안 빨개지면 그 테스트는 그 갈래를 안 재는 것이다. 역검증 결과도 본문에 적는다.

## 머지

**조건을 갖춘 내 PR 은 이 스킬이 넣는다.** 보고만 하고 두지 않는다 — 승인이 끝난 PR 을
방치하면 base 가 낡아 `#559` 가 말한 「초록인데 합친 결과는 안 쟀다」 상태로 미끄러진다.

조건 넷을 **한 번에** 확인한다.

```bash
# 내 것이고 · 전원 승인(라벨 없음)이고 · 합친 결과가 CLEAN 인가
gh pr view N --json author,reviewDecision,labels,mergeable,mergeStateStatus

# 그리고 이 브랜치를 base 로 삼는 자식 PR 이 없는가 — 전수로 본다
gh pr list --state open --json number,baseRefName,headRefName
```

| 조건 | 값 |
|---|---|
| 작성자 | 나 (남의 PR 은 초록이어도 안 한다) |
| 라벨 | **없음** — 라벨이 하나라도 있으면 아직 누군가의 손에 있다 |
| 상태 | `MERGEABLE` · `CLEAN` (`UNSTABLE` 은 체크가 빨갛거나 도는 중) |
| 자식 | 이 브랜치를 base 로 하는 열린 PR 이 **0건** |

```bash
gh pr merge N --merge --delete-branch      # 자식이 없을 때만 --delete-branch
```

❗**`reviewDecision` 만 보고 판단하지 않는다.** 그 값은 「승인이 하나라도 있고 변경요청이
없나」에 가까워서, **다른 리뷰어가 아직 안 본 상태**도 `APPROVED` 로 나온다. 판정의 정본은
라벨이다(`CLAUDE.md` §PR 리뷰 라벨 — 행동이 필요한 상태에만 라벨이 있다).

**스택은 밑에서부터다.** base 가 `main` 이 아닌 PR 은 승인돼 있어도 먼저 넣지 않는다 —
넣으면 `main` 이 아니라 **부모 브랜치**로 들어가서 부모 PR 에 커밋이 얹힌다. 부모를 먼저
넣고, 자식 base 를 `main` 으로 돌린 뒤에 넣는다.

머지한 뒤에는 **무엇이 같이 닫혔는지** 본다 — `Closes #N` 이 걸린 이슈가 있으면 그만큼
내 할 일이 줄었다.

## 리뷰

남의 PR 을 볼 때도 같다. 변경분을 읽는 것으로 끝내지 말고 **주장을 재현한다.**
찾은 것은 「무엇이 · 어디서 · 어떻게 실패하나」로 적는다. 승인·변경요청은 근거가 붙을 때만 낸다.

## 함정

**리뷰어를 여럿 요청할 때 `gh pr edit --add-reviewer` 를 쓰지 않는다 — 교체다.**
API 로 한 번에 넣고, 넣은 뒤 세어 본다.

```bash
gh api -X POST repos/OWNER/REPO/pulls/N/requested_reviewers \
  -f 'reviewers[]=alice' -f 'reviewers[]=bob'
gh pr view N --json reviewRequests -q '[.reviewRequests[].login]|join(", ")'
```

**라벨을 손으로 붙이지 않는다.** `pr-review.yml` 이 붙이고 뗀다. 방금 리뷰어를 요청한
직후에는 라벨이 아직 옛 값이다 — 워크플로가 돌 때까지 기다린다.

**가드가 `error` 면 승인을 더 받으러 가지 않는다** — 판정을 못 한 것이므로 워크플로를
다시 돌린다. `failure` 여야 승인 부족이다. 라벨과 커밋 상태가 어긋나 보이면 **참인 쪽은
커밋 상태다.** 승인이 마지막 사건인데 푸시가 없는 PR 은 라벨이 안 낫는다 — 아무 커밋이나
한 번 밀면 맞춰진다.

**본문에 백틱이 있으면 `--body-file` 로 낸다.** `gh pr comment --body "$(cat <<'EOF' … EOF)"`
는 heredoc 이 quoted 여도 `$()` 안에서 백틱이 명령 치환으로 새는 경우가 있다 — 그때
**코멘트는 올라가고 그 자리만 빈다.** 에러는 터미널에만 남으므로 올린 뒤 본문을 확인하지
않으면 모른다(실제로 `#610` 에서 한 번 냈다). 파일로 쓰고 `--body-file` 을 주면 셸을
안 지난다.

```bash
cat > "$TMP/c.md" <<'BODY'
… 백틱 든 본문 …
BODY
gh pr comment N --body-file "$TMP/c.md"
```

## 사이클을 닫는다

한 바퀴가 끝나면 **무엇을 했고 무엇이 남았는지**를 사용자에게 적는다. 아무것도 안 바뀌었으면
그것도 한 줄로 적는다 — 조용한 사이클과 못 돈 사이클이 같아 보이면 안 된다.

```
처리        #606 새로 냄 (이슈 #605 ⓐ) · #581 에 상태 알림
기다림      #581 오준서 승인 · #602 오준서 리뷰 · #606 리뷰 둘
남음        내 이슈 8건 — 다음 사이클에 #589
```

# 결정 로그 훑기

PR 스레드에서 합의된 것이 **코드에는 반영됐지만 레포에 근거가 없는** 경우가 반복돼서 만든
문서들이다. 이 스킬은 그 옮기는 작업의 **절차**다.

## 규칙은 여기 적지 않는다

무엇을 어디에 적는지, 뒤집힌 결정을 어떻게 다루는지는 **이미 문서에 있다.**

| 규칙 | 어디 |
|---|---|
| ADR vs 결정 로그 · 본문 복제 금지 | `docs/decision-log.md` → `## ADR 과의 관계` |
| 행 추가 · 철회 표기 · ADR 승격 | `docs/decision-log.md` → `## 갱신 규칙` |
| 출처·상태 표기 | `docs/decision-log.md` → `## 표기` |
| ADR 은 삭제·수정하지 않는다 | `CLAUDE.md` → `## 설계 결정 기록` |
| 소유권·계약 변경 승인 | `CLAUDE.md` → `## 소유권과 기여 규칙`, `contracts/` |

**여기에 옮겨 적지 말 것.** 두 벌이 되면 갈리고, 갈린 걸 아무도 모른다 — 이 레포가
`CanonicalJson` 을 한 벌만 두는 이유, `pr-review-guard` ↔ `pr-reviewer-label` 이 한 쌍인
이유와 같다. 규칙이 바뀌면 그 문서를 고치고 이 파일은 그대로 둔다.

## 절차

### 1. 무엇이 새로 오갔는지 뽑는다

```bash
./.claude/skills/decision-sweep/sweep.sh
```

워터마크(`decision-log.md` 의 `어디까지 훑었나` 표에서 가장 늦은 시각)를 읽어서, 그 뒤로
갱신된 PR·이슈의 **본문 · 리뷰 본문 · 인라인 리뷰 코멘트 · 이슈 코멘트**를 덤프한다. 이미
훑은 항목은 본문을 건너뛰고 새 코멘트만 낸다.

시각을 직접 주려면 `./sweep.sh 2026-08-26T07:00:00Z`.

### 2. 읽는다 — 진단이 아니라 **합의**를 찾는다

결정은 대개 이런 모양으로 스레드에 있다.

- *"~로 가자"* / *"~가 맞다"* — 확정
- 리뷰가 짚고 작성자가 받아들인 것 — 확정 (승인 리뷰 안에도 있다)
- 한쪽이 물었고 답이 아직 없는 것 — **10절 미결**, 담당과 시점을 적는다
- 결함 보고 그 자체 — 결정이 아니다. 고치기로 한 *방향*이 결정이다

### 3. 어디에 적을지 가른다

```
원칙급이고, 뒤집으려면 새 문서가 필요한가 ──── 예 → docs/adr/ 에 새 ADR
                                                     (결정 로그에는 번호 참조만)
계약·규약·배선이 확정됐는가 ──────────────── 예 → 해당 절에 행 추가
아직 안 정해졌거나 남의 답을 기다리는가 ──── 예 → 10절 (담당 · 시점 필수)
```

ADR 후보인데 확신이 없으면 **11절(`ADR 로 승격할 후보`)에 넣고 넘긴다.** ADR 을 늘리는 것보다
잘못 늘린 ADR 을 되돌리는 게 비싸다.

### 4. 적는다

기존 행이 있으면 **그 행을 갱신한다.** 새 행을 만들면 같은 결정이 두 벌이 되고, 나중에
읽는 사람이 어느 쪽이 최신인지 알 수 없다. 닫힌 미결은 지우지 않고 `→` 로 결과를 잇는다.

### 5. 워터마크를 넣는다

`sweep.sh` 가 마지막에 찍어주는 행을 `어디까지 훑었나` 표에 추가한다.

## 함정 — 다 실제로 났던 것이다

**1. 번호로 기록하면 이미 훑은 항목의 새 코멘트를 놓친다.**
`#1~#52` 식으로 적으면 *그 항목이 존재했다*만 말하고 *그 뒤로 무슨 말이 오갔는지*는 말하지
않는다. 이슈 #37·#41 이 8/25 범위 안이었는데 8/26 01:39 에 배포 형태·`data/` 마운트·자격증명이
한꺼번에 확정됐다 — 번호로 봤으면 인프라 확정 전부를 놓쳤다. **그래서 기준은 시각이다.**

**2. 워터마크를 앞당겨 적으면 그 구간이 영구히 건너뛰어진다.**
워터마크는 "훑은 시각"이 아니라 **"이 시각까지의 말을 다 읽었다"는 주장**이다. 검색을
08:35 에 돌리고 09:00 을 적으면, 08:45 에 달린 코멘트를 읽었다고 거짓 주장하는 것이고 다음
훑기는 09:00 부터 시작하므로 **그 코멘트는 아무도 안 읽는다.** `sweep.sh` 가 검색 시각에서
5분을 빼는 이유다 — 겹쳐 읽는 건 공짜고, 건너뛰는 건 안 보인다.

**3. `gh pr view` 는 인라인 리뷰 코멘트를 주지 않는다.**
`--json comments` 는 이슈 코멘트, `--json reviews` 는 리뷰 본문이고, 코드 줄에 달린 것은
`gh api repos/{o}/{r}/pulls/{n}/comments` 에만 있다. 지금 팀은 전부 리뷰 본문에 쓰지만
(2026-08-26 확인: 인라인 0건) 누군가 쓰기 시작하면 **조용히 빠진다.** `sweep.sh` 는 셋 다 본다.

**4. 승인 리뷰에도 결정이 들어 있다.**
`APPROVED` 를 "읽을 것 없음"으로 넘기면 안 된다. #109 의 승인 리뷰가 `build.gradle` 입력
등재 결정을 담고 있었고, 그게 없으면 대조 테스트가 아예 돌지 않았다.

**5. 표 칸 수가 어긋나면 렌더가 조용히 깨진다.**
행을 손으로 넣거나 스크립트로 치환하면 `|` 개수가 틀어진다. 아래 검증을 돌린다.

**6. 원문자(`①②③`)를 쓰지 않는다.** 팀원 환경에서 안 보인다. `1.` `2.` `3.` 을 쓴다.

**7. 남의 영역 결정을 옮길 때는 이해한 대로 적었다고 밝힌다.**
이 문서는 결정을 *만들지* 않는다. 사실과 다르면 정정받아야 하므로, PR 코멘트에 무엇을
새로 적었는지 덩어리별로 드러낸다.

## 검증

행을 넣은 뒤 반드시 돌린다.

```bash
./.claude/skills/decision-sweep/check.sh          # 기준은 origin/main
./.claude/skills/decision-sweep/check.sh origin/main
```

`!!` 로 나온 것은 고쳐야 하고, `?` 로 나온 것은 **질문이다** — 답이 "그래도 맞다"일 수 있다.
질문까지 실패로 막으려면 `SWEEP_STRICT=1`.

| | 검사 | 왜 |
|---|---|---|
| `!!` | 표 칸 수 | 절마다 칸 수가 다르므로 구분선 앞줄을 헤더로 잡는다. 이스케이프된 `\|` 는 셀 구분이 아니라 본문이라 세지 않는다 |
| `!!` | 원문자 | 팀원 환경에서 렌더되지 않는다. 출처 열의 항목 지시도 `#28 (4번)` 처럼 적는다 |
| `!!` | ADR 링크 | 결정 로그가 가리키는 `adr/*.md` 가 실재하는가 |
| `!!` | ADR 연번 | `docs/adr/` 는 연번이다. 구멍이 있으면 번호를 잘못 붙였거나 파일이 빠졌다 |
| `!!` | 미결 담당자 오타 | 이름이 한 글자 틀리면 그 행은 **아무의 것도 아닌 채로 남는다.** 미결은 원래 안 움직이니 안 움직여도 이상해 보이지 않는다. 이름 표는 `.github/workflows/pr-review.yml` 에서 읽는다 — **못 찾으면 건너뛰지 않고 `!!` 다**(#306 이 워크플로를 합쳤을 때 이 검사가 조용히 쉬었다) |
| `?` | 기존 ADR 수정 | ADR 은 append-only 다. 결정 문면이 바뀌었으면 새 ADR 로 간다. 표기·오타 수정이면 그대로 진행하고 PR 에 diff 를 보인다 |
| `?` | 미결 무주 | 담당에 이름이 없다. `3인`·`승인 대기` 처럼 정당한 것도 있다 |
| `?` | 지난 기한 | 미룬 것인지 잊은 것인지 |

**오타 검사는 "유효한 이름과 한 글자만 다른 것"만 잡는다.** 3음절 한국어 낱말을 다 잡으면
노이즈가 나고, 노이즈가 나면 아무도 안 쓴다.

`check.sh` 가 규칙을 아는 유일한 자리다. 검사 로직을 이 파일에 옮겨 적지 않는다 — 그러면
검사가 두 벌이 되고, 스크립트를 고쳐도 문서가 옛 규칙을 말한다.

## 커밋과 PR

- 브랜치: `docs/decision-log-sweep-<기준PR번호>` (기존 훑기 PR 이 열려 있으면 거기에 얹는다)
- 커밋 메시지에 **덩어리별로 몇 건인지**와 새 워터마크 시각을 적는다
- PR 코멘트에 새로 적은 것만 덩어리로 낸다 — 앞서 승인받은 부분은 그대로임을 밝힌다
- `docs/` 는 정세현 소유다. 다른 사람이 훑었으면 정세현 리뷰를 받는다
- 커밋·PR 본문에 `Co-Authored-By` / `🤖 Generated` 줄을 넣지 않는다

## 이 스킬이 못 하는 것

- **결정을 만들지 않는다.** 스레드에 합의가 없으면 10절 미결로 적고 담당을 지정한다
- **계약(`contracts/`)을 고치지 않는다.** 계약 변경은 강희진 승인 + 수요자 전원 멘션이다
- **ADR 을 뒤집지 않는다.** 결정이 바뀌면 새 ADR 을 추가하고 기존 문서는 상태만 갱신한다

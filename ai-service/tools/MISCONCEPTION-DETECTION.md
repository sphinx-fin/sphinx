# 오해 탐지 — 일곱 방법을 다 재고 비교한 기록 (2026-09-04)

> **같은 시도를 다시 하기 전에 이 문서를 읽는다.** 일곱 중 여섯이 실측에서 떨어졌고,
> 떨어진 이유가 전부 같다. 소유: 윤지석 (F-DET-001 / F-SCR-001)

## 문제

고객이 되말한 발화에서 **오해(U4)** 를 잡는다. `U4` 는 게이트에서 `R-01` → RED 라
**판매를 막는다.** 그래서 두 방향이 다 비싸다.

```
미탐   오해한 고객에게 판다              나중에 분쟁
오탐   이해한 고객의 계약을 막는다        정상 거래를 막는다
```

기준선(`#357` 사람 라벨 70건, 합의 51건):

```
사람 2인 QWK 0.769 · 일치율 72.9%       ← 천장
U4 이진 일치율 88.6% · Cohen κ 0.741    ❗우연 보정하면 4단계와 같다
불일치 19건 중 U1↔U2 가 9건 (47%)       ← 제일 갈리는 경계
```

❗**기준선은 과제마다 다르다 — 지표와 같은 과제의 것을 쓴다.**

```
4단계 최빈 등급 (U4)          31~37%      ← 4단계를 예측하는 지표의 기준선
이진 「항상 비U4」 (32/51)     63%         ← U4 이진 판정의 기준선
```

이 둘을 섞은 것이 아래 「방법론」 표 다섯째 줄의 오류 (b) 다.

## 결과 표

| 방법 | 미탐 | 오탐 | 판정 | 근거 |
|---|---|---|---|---|
| 어휘 매칭 (현행 1·2단계) | **100%** | 0% | ❗안전망으로도 안 선다 | 51건 중 **발동 0건** |
| **LLM 한 콜 (`#366`)** | **11.1%** | **4.7%** | **✅ 머지됨** | 조건을 하나씩 짚게 한다 |
| 쌍별 LLM (조건마다 1콜) | 10.5% | **12.5%** | ❌ | 오탐이 네 배 |
| 문장 임베딩 | — | — | ❌ | 정반대가 `+0.623`, 같은 뜻이 `+0.571` |
| 바이그램 그림자 (`#364`) | — | — | ❌ | 70건 적중 1건, **그게 오탐** |
| 기성 NLI (KLUE) | — | — | ❌ | 전수 모순율 24% |
| NLI 양방향 + 술어 정렬 | — | — | ❌ | 커버리지 17%, P5 반대 오류 1건 |

**분모** — 미탐은 합의 U4 기준, 오탐은 합의 비U4 기준이다.

```
합의 51건 = U4 19 · 비U4 32
U4 분모가 18 인 줄이 있다 — els-0053(자기정정)은 정답이 `#363` 미결이라 뺀다

어휘 매칭     19/19 = 100%  ·  0/32 = 0%     tools/tune_ngram_threshold.py
LLM 한 콜     2/18 = 11.1%  ·  2/43 = 4.7%   app/prompts/F-SCR-001_v3.md 의 표
쌍별 LLM      2/19 = 10.5%  ·  4/32 = 12.5%
```

❗**첫 판(`57c8bd1`)의 1행이 `16.7%` 였다. 그 숫자는 어휘 매칭 것이 아니다** —
`F-SCR-001_v3.md` 의 판본 비교표에 있는 **v2 프롬프트의 미탐 `3/18`** 이고, 그것을 어휘
매칭 행에 붙였다. 그래서 *"안전망으로 유지"* 라는 판정까지 딸려 나왔다. **어휘 매칭은
그 시점에 한 번도 측정되지 않았다.** 아래 「어휘 매칭」 절이 처음으로 잰다.

**같은 표 안에서 행이 섞였기 때문에 모집단 대조로는 안 잡혔다** — 분모 `18` 이 실제로
이 코퍼스의 값이라 그럴듯했다. 숫자마다 **어느 방법의 것인지**를 재현 명령과 함께 적는
것이 유일한 방어다. (`2/43` 의 `43` 이 무엇의 분모인지는 `F-SCR-001_v3.md` 에도 적혀
있지 않다 — 남은 미결 하나.)

## 여섯이 떨어진 이유는 하나다

**닮음을 재고 있었다. 오해는 닮음이 아니라 「반대되는 믿음」이다.**

❗**셈이 하나 늘었다.** 첫 판은 어휘 매칭을 *"안전망으로 유지"* 로 두고 「다섯이 떨어졌다」
고 셌다. 어휘 매칭을 실제로 재 보니 그것도 안 선다 — **일곱 중 서는 것은 `LLM 한 콜`
하나다.** 아래 `test_the_fallen_count_matches_the_table` 이 이 셈을 표와 대조한다.

```
어휘·바이그램   형태가 닮으면 붙는다
임베딩          주제가 닮으면 붙는다
기성 NLI        술어가 같을 때만 모순을 본다
```

### 어휘 매칭 — 문턱 `0.62` 를 처음으로 실측했다

`NGRAM_THRESHOLD = 0.62` 는 첫 커밋(`96ab471`)에 **손으로 들어간 값**이고, 그때 붙인
주석이 스스로 *"튜닝 시 dev set으로 재측정한다"* 고 적었다. **그 재측정이 없었다.**
`#368` 이 값을 `app/scoring_thresholds.yaml` 로 옮겼지만 *"왜 0.62 인가"* 는 빈 칸이었다.

```
양성(합의 U4  n=19)   최고 포함도 0.364
음성(합의 비U4 n=32)   최고 포함도 0.333      ← 겹친다. 가를 수 있는 값이 없다

문턱 0.38 ~ 1.00      미탐 19 · 오탐 0       ← 0.62 를 포함한 전 구간이 평평하다
문턱 0.34             미탐 18 · 오탐 0
문턱 0.30             미탐 15 · 오탐 2
```

**0.38 위 어디에 놓아도 발동이 0 이다** — `0.45` 든 `0.95` 든 동작이 같다. 실제 매처를
그대로 돌려도 **51건 중 등급을 바꾼 횟수 0** 이다.

낮추는 쪽은 P5(미탐 최소화)라는 논거가 있으니 따로 셌다. floor 는 **모델이 U4 를 안 냈을
때만** 등급을 움직이므로 모델 판정을 겹쳐 세야 한다.

```
0.30 으로 낮추면 6건이 뒤집힌다
  무해 (모델이 이미 U4)   3건
  ✅ 미탐 구제             1건   els-0049
  ❌ 오탐 신설             2건   els-0033 · els-0060
```

**1건 구제에 2건 오탐이다.** 오탐 하나는 floor → `U4` → 게이트 `R-01` → **RED(판매
차단)** 로 직결되므로 어느 방향으로도 못 받는다. 그리고 `els-0060` 이 이 방법의 성격을
그대로 보여 준다.

```
발화   "이건 예금이 아니라 증권사가 자기 이름으로 찍어내는 거라,
        나라에서 지켜 주는 것도 없고 …"          사람 라벨 U1 — 정확한 이해다
패턴   M01-PRINCIPAL-GUARANTEE "원금은 지켜지는"   포함도 0.333
```

「지켜 주는」과 「지켜지는」이 겹쳐서 붙는다. **뜻이 정반대인데 형태가 닮았다** — 강희진의
`#364`(*"예금자보호는 **안** 된다고 하셨죠"* → 0.71)와 같은 모양이고, 아래 「닮음을 재고
있었다」의 첫 사례다.

#### 왜 죽어 있었나 — 그리고 왜 안 보였나

```
eval 코퍼스 (독립 작성)      51건 중 발동  0건 ( 0%)
내 dev set (패턴에서 씨앗)   35건 중 발동  9건 (26%)
```

**1단계는 "라이브러리에 그 말이 이미 적혀 있는 경우" 고, 2단계는 그 어미·조사 변형만
덮는다.** 남이 쓴 발화에는 둘 다 닿지 않는다. 내 dev set 은 씨앗을 `misconceptions.yaml`
패턴에서 따왔으니 26% 가 걸리고, **그래서 이 단계가 살아 있는 것처럼 보였다** — `#266`
에서 *"등급 24/24 일치"* 를 근거로 낸 것과 **같은 오염**이다.

→ **문턱을 다시 정하는 것으로는 못 고친다.** 값이 임의인 것은 사실이지만 바꿀 값이
없다. 2단계는 안전망이 아니라 **잠들어 있는 코드**이고, 그 사실이 기록되는 것이
재측정의 산출물이다. 지우지 않는 이유는 `#369`(pgvector)·`#358`(리랭킹)이 이 자리를
대체 후보로 보고 있어서다 — 대체가 정해질 때 같이 본다.

재현: `tools/tune_ngram_threshold.py` (LLM 호출 없음 · 결정론)

### 임베딩 — 눈금을 먼저 봐야 한다

`text-embedding-3-small` (1536차원, 단위벡터). 구현은 정확하다(항등 `+1.0000`, 부호 반전
`-1.0000`). **틀린 것은 `0` 이 바닥이라는 가정**이었다.

```
무관한 문장 쌍 10개   cos +0.123 ~ +0.236 (평균 +0.158)   ← 바닥값

기준 "원금은 지켜지는" (오해 패턴)
  +0.660  "원금이라는 말이 무슨 뜻인가요"    ← 1등이 「모르겠다」는 질문
  +0.644  "원금은 보장됩니다"        같은 뜻
  +0.623  "원금은 보장되지 않습니다"   ❗정반대
  +0.571  "원금 손실은 없습니다"      같은 뜻 — 정반대보다 낮다
  +0.320  "수수료는 어떻게 되나요"
```

`text-embedding-3-large` 는 **더 나빴다** — 주제 표현이 정교해질수록 긍정·부정이 가까워진다.
대조 극 두 개(topic·margin)로 갈라도 겹쳤다: M02 의 **이해** 발화가 margin `+0.055` 로
M01 의 **오해** 발화 전부(`-0.12`)보다 높다.

재현: `tools/tune_embedding_threshold.py` (실 LLM 호출)

### 바이그램 — 같은 벽의 다른 층 (`#364`, 강희진)

```
"예금자보호는 **안** 된다고 하셨죠"  ↔  조건 "예금자보호가 된다"   0.71 → U4
사람 라벨 U1/U2 — 올바른 이해다
```

**70건에서 (b) 가 잡는 유일한 1건이 오탐이었다.**

### 기성 NLI — 조건이 드러났다

`Huffon/klue-roberta-base-nli`. 4쌍으로는 `0.999` 로 갈렸는데 **전수 82쌍에서 24%** 다.

```
무리   모순율     설명
A       40%     정답↔오해 극성이 이미 반대인 항목 (2개)
B       31%     술어를 맞춰 쓸 수 있는 항목 (7개)
C       18%     축이 다른 항목 (8개) — 정도·수량사·범주

❗ENTAILMENT (정답과 오해를 같다고 본다)
   0.99  오해 "예금처럼 전액 보호된다"  ↔ 정답 "보호 한도가 있다"
   0.98  오해 "낸 보험료 전액이 보호"    ↔ 정답 "보호 한도가 있다"
   0.53  오해 "모든 기초자산이 함께"     ↔ 정답 "어느 하나라도 성립"
```

**정면으로 반대인 명제를 `0.99` 로 함의라 한다.** 「전액↔한도」·「모두↔하나라도」는
극성 축이 아니다.

문면 민감도는 낮다 — 네 가지 가설 문면에서 **83% 가 같은 판정**, 모순율은 17~24% 로
문면과 무관하다. **즉 낮은 모순율의 원인이 문면이 아니라 명제 자체다.**

### 술어 정렬 + 양방향 NLI — 커버리지가 안 오른다

오해 조건 22개에 **술어를 맞춘 정면 반박**을 써서, 발화 ↔ 조건과 발화 ↔ 반박을 둘 다
보고 **반대로 나올 때만 판정**하게 했다(확신 없으면 추상).

```
판정한 것   4/23 (17%)      ← 83% 를 추상으로 넘긴다
맞은 것     3/4
틀린 것     els-0064  사람 U4  →  「이해」      ❗P5 반대 방향
```

정렬해도 오르지 않는 이유: 술어를 맞추는 것은 **조건과 반박 사이**이고, **발화와 조건
사이의 거리는 그대로**다. 고객은 조건 문면을 안 따라 한다.

**「추상」 구조 자체는 살릴 값이 있다** — 어느 부품을 쓰든 확신 없으면 답하지 않는 틀은
유지해야 한다.

### 쌍별 LLM — 미탐을 오탐과 3배로 바꾼다

```
             미탐            오탐          호출/항목
한 콜 (#366)  3/19 (15.8%)  1/32 ( 3.1%)     1
쌍별          2/19 (10.5%)  4/32 (12.5%)   2.6
```

오탐 4건이 전부 **U2·U3 를 U4 로** 올린 것이다 — 등급 맥락 없이 *"이 믿음을 갖고 있나"* 만
물으면 모델에게 *"모른다"* 라는 선택지가 없다.

게이트에서 비용이 대칭이 아니다.

```
미탐 → R-04 YELLOW → 재설명 루프가 받고, 2회 소진하면 R-03 이 RED   뒤에서 한 겹 더 잡힌다
오탐 → R-01 RED                                                 그 자리에서 끝난다
```

## 유일하게 통한 것 — LLM 한 콜, 조건을 하나씩 (`#366`)

```
1단계  오해 조건을 **하나씩** 짚는다. 각 조건마다 "고객이 이 믿음을 갖고 있는가"
       ❗문면이 같은지가 아니라 믿음이 같은지를 본다
       하나라도 걸리면 거기서 U4. 2단계로 안 내려간다
2단계  오해가 없을 때만 필수 요소 충족 개수를 센다 (u1_requires)
```

**순서가 결과를 바꿨다** — *"U4 우선"* 을 세라는 지시 **뒤에** 붙였을 때는 모델이 먼저 세고
부분점수를 줘서 미탐 하나가 `U2 → U1` 로 **더 나빠졌다**(리포트에서 0건이던 갈래).

## ❗방법론 — 같은 함정에 다섯 번 빠졌다

**작은 표본에서 본 것을 큰 표본으로 옮길 때 조건이 바뀌면, 무엇을 잰 건지 알 수 없다.**

| | 작은 표본 | 전수 | 바뀐 조건 |
|---|---|---|---|
| 자기정정 | — | — | 미결 규칙(`#363`)을 프롬프트가 먼저 정했다 |
| 「상쇄 금지」 | 5건 중 4/5 | 미탐 2→3 | 문장 하나를 더했다 |
| 쌍별 1차 | 2건 다 잡힘 | 미탐 5/19 | 프로브→전수에서 시스템 프롬프트에 한 줄 |
| NLI | 4쌍 `0.999` | 모순율 24% | 가설 술어를 내가 손으로 맞춰 줬다 |
| **종결어미 누설** | **95%** | **51~57%** | ❗**조건이 바뀐 게 아니라 조건이 안 적혀 있었다** |

### 다섯째 줄은 이 문서 자신이다 (`#385` 리뷰 · 정세현 · 강희진)

첫 판이 *"종결어미 6자만으로 라벨을 **95%** 맞힌다(기준선 63%)"* 라고 적었다. **두 사람이
각각 재서 안 나왔고, 두 사람이 맞다.**

**프로토콜 — 이제 적는다.**

```
끝 6자가 같은 **다른** 행의 최빈 등급 · leave-one-out · 짧은 쪽 백오프 · 전 행 정확도

              기준선(최빈)   끝6자 LOO+백오프
정세현 라벨 70쌍     34%            57%
강희진 라벨 70쌍     31%            51%
```

**라벨러를 갈라 적는다.** 한 값만 적으면 *"어느 라벨로 잰 건가"* 가 또 빠지고, 6%p 차이
자체가 *"이 숫자는 표본과 라벨에 따라 움직인다"* 를 말해 준다. 참고로 내 dev set 으로
재면 26%(기준선 56%)로 **기준선 아래**다(`#378` 리뷰).

**내 95% 는 어디서 나왔나 — 오류가 둘이다.**

```
(a) 형태를 라벨을 보고 골랐다
    「거죠」가 U4 8/9, 「거네요」·「라는 거죠」가 U1 로 쏠린 것을 먼저 보고
    그 형태들만 화이트리스트로 골랐고, 같은 51행에서 채점했다 → 판정 19/51 (37%)
    ❗LOO 로도 안 고쳐진다 — 규칙 자체가 그 51행에서 나왔으니 뺄 행이 없다.
    정세현이 짚은 싱글턴 누설(끝6자 그룹의 44%가 1건)보다 한 겹 강하다.
    참고: 「그룹이 만장일치면 예측」 규칙은 구조적으로 100% 다 (판정 35/51, 싱글턴 77%).

(b) 기준선이 다른 과제 것이다
    63% = 항상 「비U4」인 **이진** 기준선(32/51)인데, 지표는 4단계 예측 정확도였다.
    4단계 최빈 기준선은 31~37% 다. 지표와 기준선이 같은 과제여야 한다.
```

**살아남는 것 — 서술 주장은 정확히 재현된다.**

```
합의 U1 총 7건 · 그중 「거네요」·「라는/다는 거죠」에 7건 (예외 없음)
그 형태들의 U4  0건
```

이건 **예측 정확도가 아니라 코퍼스에 대한 서술**이라 누설과 무관하다. 누설을 말하는 정직한
형태가 이쪽이다 — *"U1 이 두 형태에 전부 몰려 있고 그 형태에 U4 가 없다"*.

**결론은 안 흔들리고 크기가 흔들린다.** 기준선의 **1.6~1.8배**이므로 누설은 실재하고
`#378`(화법 넓히기) 처방도 맞다. 다만 `95%`(*"내용을 안 봐도 거의 다 맞는다"*)와
`51~57%`(*"기준선보다 낫지만 절반은 틀린다"*)는 **근거의 무게가 다르다.**
`#354` 가 잡은 **위치** 누설과 다른 축이라 섞어도 안 없어진다는 것은 그대로다.

❗**이 줄이 위 표의 다섯째다.** 앞의 넷은 *조건이 바뀐* 것이고 이것은 *조건이 안 적힌*
것이다 — 그리고 「재현」 절이 ①②③ 명령을 다 적었는데 **이 숫자만 재현 경로가 없었다.**

## 남은 길 — 둘

### ① 루브릭 술어 정렬 (내 파일, 지금 가능)

무리 A·B 9개 항목의 조건에 정면 반박을 써 뒀다(`tools/condition_counters.py`, 21개).
**지금 판정에 안 쓰지만**, MiniCheck 식 학습을 하면 **조건 ↔ 반박 쌍이 곧 모순 라벨**이라
합성 데이터의 씨앗이 된다. `tests/test_condition_counters.py` 가 루브릭 실물과 대조한다.

### ❗쓰면서 나온 것 둘

**부정 표지 정규식이 두 번 빗나갔다.**

```
못한       만 보면  "받지 **못할** 수 있다"    를 놓친다
못[하할함해] 로 좁히면 "돌려받지 **못한다**"    를 놓친다 (못 + 한다)
→ `못` 뒤를 제한하지 않는다. 이 맥락에서 `못` 은 항상 부정 보조다
```

**조건 하나를 뺐다 — 한 문장에 두 극성이 있다.**

```
"원금은 보장되고 이자만 못 받는다"     「보장된다」 긍정 + 「못 받는다」 부정
→ 극성을 뒤집을 수가 없다. 억지로 쓰면 뜻이 반쪽만 반대가 된다
→ **먼저 쪼개야** 대조 대상이 된다 (`#367` 과 같은 모양: 한 조항에 사실이 둘)
```

`#367`(요소 하나에 사실이 둘)이 **요소 쪽 사례**였는데, **조건 쪽에도 같은 것이 있다**는
것이 이 작업에서 나왔다. 22개 중 21개만 남은 이유다.

### ② 도메인 소형 모델 (3주차 이후) — 종착지

기성 부품이 우리 축(정도·수량사·범주)을 안 덮는다는 것이 이 측정의 결론이다.
[MiniCheck](https://arxiv.org/abs/2404.10774) 가 같은 과제 모양에서 **합성 학습 데이터로
770M 모델이 GPT-4 수준·1/400 비용**을 냈다. 우리에 맞는 이유가 셋이다.

```
합성으로 학습    라벨 70건으로는 학습이 안 되는 제약을 우회한다. 상품 조건이 정형이라 궁합이 좋다
로컬 실행        proposal.md:419 — "외부 LLM API 를 그대로 호출하는 구조는 재위탁 문제를
                일으킨다. 국내 인프라와 전용 배포를 전제로 설계한 이유다."
                → **호출 비용 · 결정론 · 망분리가 한 문제다**
문장 단위        절 단위 분할과 맞물린다
```

한계: 영어 기준 학습이라 한국어 부정 처리가 미검증. **접근법을 참고해 한국어로 다시 만드는
쪽**이 현실적이고, `KLUE-NLI`(실제 한국어에서 만든 첫 NLI, CC-BY-SA)가 출발점이다.

### 준비물 — 이미 확인한 것

`kiwipiepy`(C++·로컬·결정론)가 필요한 신호를 태그로 분리한다.

```
발화                          부정      종결(EF)   전언
"원금은 보장되지 않습니다"          않/VX     습니다     -
"원금은 지켜지는 거죠?"            -          죠      -
"예금자보호는 안 된다고 하셨죠"      안/MAG      죠      O
"손실이 날 수도 있다는 거네요"       -         네요     -
```

`-네요`(깨달음) 대 `-거죠`(확인 요구)를 정규식으로는 앞 글자를 봐야 갈리는데 `EF` 태그로
정확히 뗀다. **전언(`-다고 하셨죠`)이 구조로 잡히는 것**도 값이 있다 — 판매자 발화 인용을
고객 자기 믿음과 갈라내는 자리다.

❗**다만 종결어미를 신호로 쓰는 것은 `#377` 이 닫힌 뒤다.** 지금 표본에서는 그 신호의
강도를 믿을 수 없다.

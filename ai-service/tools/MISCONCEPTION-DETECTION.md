# 오해 탐지 — 여섯 방법을 다 재고 비교한 기록 (2026-09-04)

> **같은 시도를 다시 하기 전에 이 문서를 읽는다.** 여섯 중 다섯이 실측에서 떨어졌고,
> 떨어진 이유가 전부 같다. 소유: 윤지석 (F-DET-001 / F-SCR-001)

## 문제

고객이 되말한 발화에서 **오해(U4)** 를 잡는다. `U4` 는 게이트에서 `R-01` → RED 라
**판매를 막는다.** 그래서 두 방향이 다 비싸다.

```
미탐   오해한 고객에게 판다              나중에 분쟁
오탐   이해한 고객의 계약을 막는다        정상 거래를 막는다
```

기준선(`#357` 사람 라벨 70건, 합의 51건):

```
사람 2인 QWK 0.769 · 일치율 72.9%       ← 천장
U4 이진 일치율 88.6% · Cohen κ 0.741    ❗우연 보정하면 4단계와 같다
불일치 19건 중 U1↔U2 가 9건 (47%)       ← 제일 갈리는 경계
```

## 다섯이 떨어진 이유는 하나다

**닮음을 재고 있었다. 오해는 닮음이 아니라 「반대되는 믿음」이다.**

```
어휘·바이그램   형태가 닮으면 붙는다
임베딩          주제가 닮으면 붙는다
기성 NLI        술어가 같을 때만 모순을 본다
```

### 임베딩 — 눈금을 먼저 봐야 한다

`text-embedding-3-small` (1536차원, 단위벡터). 구현은 정확하다(항등 `+1.0000`, 부호 반전
`-1.0000`). **틀린 것은 `0` 이 바닥이라는 가정**이었다.

```
무관한 문장 쌍 10개   cos +0.123 ~ +0.236 (평균 +0.158)   ← 바닥값

기준 "원금은 지켜지는" (오해 패턴)
  +0.660  "원금이라는 말이 무슨 뜻인가요"    ← 1등이 「모르겠다」는 질문
  +0.644  "원금은 보장됩니다"        같은 뜻
  +0.623  "원금은 보장되지 않습니다"   ❗정반대
  +0.571  "원금 손실은 없습니다"      같은 뜻 — 정반대보다 낮다
  +0.320  "수수료는 어떻게 되나요"
```

`text-embedding-3-large` 는 **더 나빴다** — 주제 표현이 정교해질수록 긍정·부정이 가까워진다.
대조 극 두 개(topic·margin)로 갈라도 겹쳤다: M02 의 **이해** 발화가 margin `+0.055` 로
M01 의 **오해** 발화 전부(`-0.12`)보다 높다.

재현: `tools/tune_embedding_threshold.py` (실 LLM 호출)

### 바이그램 — 같은 벽의 다른 층 (`#364`, 강희진)

```
"예금자보호는 **안** 된다고 하셨죠"  ↔  조건 "예금자보호가 된다"   0.71 → U4
사람 라벨 U1/U2 — 올바른 이해다
```

**70건에서 (b) 가 잡는 유일한 1건이 오탐이었다.**

### 기성 NLI — 조건이 드러났다

`Huffon/klue-roberta-base-nli`. 4쌍으로는 `0.999` 로 갈렸는데 **전수 82쌍에서 24%** 다.

```
무리   모순율     설명
A       40%     정답↔오해 극성이 이미 반대인 항목 (2개)
B       31%     술어를 맞춰 쓸 수 있는 항목 (7개)
C       18%     축이 다른 항목 (8개) — 정도·수량사·범주

❗ENTAILMENT (정답과 오해를 같다고 본다)
   0.99  오해 "예금처럼 전액 보호된다"  ↔ 정답 "보호 한도가 있다"
   0.98  오해 "낸 보험료 전액이 보호"    ↔ 정답 "보호 한도가 있다"
   0.53  오해 "모든 기초자산이 함께"     ↔ 정답 "어느 하나라도 성립"
```

**정면으로 반대인 명제를 `0.99` 로 함의라 한다.** 「전액↔한도」·「모두↔하나라도」는
극성 축이 아니다.

문면 민감도는 낮다 — 네 가지 가설 문면에서 **83% 가 같은 판정**, 모순율은 17~24% 로
문면과 무관하다. **즉 낮은 모순율의 원인이 문면이 아니라 명제 자체다.**

### 술어 정렬 + 양방향 NLI — 커버리지가 안 오른다

오해 조건 22개에 **술어를 맞춘 정면 반박**을 써서, 발화 ↔ 조건과 발화 ↔ 반박을 둘 다
보고 **반대로 나올 때만 판정**하게 했다(확신 없으면 추상).

```
판정한 것   4/23 (17%)      ← 83% 를 추상으로 넘긴다
맞은 것     3/4
틀린 것     els-0064  사람 U4  →  「이해」      ❗P5 반대 방향
```

정렬해도 오르지 않는 이유: 술어를 맞추는 것은 **조건과 반박 사이**이고, **발화와 조건
사이의 거리는 그대로**다. 고객은 조건 문면을 안 따라 한다.

**「추상」 구조 자체는 살릴 값이 있다** — 어느 부품을 쓰든 확신 없으면 답하지 않는 틀은
유지해야 한다.

### 쌍별 LLM — 미탐을 오탐과 3배로 바꾼다

```
             미탐            오탐          호출/항목
한 콜 (#366)  3/19 (15.8%)  1/32 ( 3.1%)     1
쌍별          2/19 (10.5%)  4/32 (12.5%)   2.6
```

오탐 4건이 전부 **U2·U3 를 U4 로** 올린 것이다 — 등급 맥락 없이 *"이 믿음을 갖고 있나"* 만
물으면 모델에게 *"모른다"* 라는 선택지가 없다.

게이트에서 비용이 대칭이 아니다.

```
미탐 → R-04 YELLOW → 재설명 루프가 받고, 2회 소진하면 R-03 이 RED   뒤에서 한 겹 더 잡힌다
오탐 → R-01 RED                                                 그 자리에서 끝난다
```

## 유일하게 통한 것 — LLM 한 콜, 조건을 하나씩 (`#366`)

```
1단계  오해 조건을 **하나씩** 짚는다. 각 조건마다 "고객이 이 믿음을 갖고 있는가"
       ❗문면이 같은지가 아니라 믿음이 같은지를 본다
       하나라도 걸리면 거기서 U4. 2단계로 안 내려간다
2단계  오해가 없을 때만 필수 요소 충족 개수를 센다 (u1_requires)
```

**순서가 결과를 바꿨다** — *"U4 우선"* 을 세라는 지시 **뒤에** 붙였을 때는 모델이 먼저 세고
부분점수를 줘서 미탐 하나가 `U2 → U1` 로 **더 나빠졌다**(리포트에서 0건이던 갈래).

## ❗방법론 — 같은 함정에 네 번 빠졌다

**작은 표본에서 본 것을 큰 표본으로 옮길 때 조건이 바뀌면, 무엇을 잰 건지 알 수 없다.**

| | 작은 표본 | 전수 | 바뀐 조건 |
|---|---|---|---|
| 자기정정 | — | — | 미결 규칙(`#363`)을 프롬프트가 먼저 정했다 |
| 「상쇄 금지」 | 5건 중 4/5 | 미탐 2→3 | 문장 하나를 더했다 |
| 쌍별 1차 | 2건 다 잡힘 | 미탐 5/19 | 프로브→전수에서 시스템 프롬프트에 한 줄 |
| NLI | 4쌍 `0.999` | 모순율 24% | 가설 술어를 내가 손으로 맞춰 줬다 |

그리고 **표본 자체가 신호를 흘릴 수 있다**(`#377`) — eval 70건에서 **내용을 하나도 안 보고
종결어미 6자만으로 라벨을 95% 맞힌다**(기준선 63%). `#354` 가 잡은 **위치** 누설과 다른
축이라 섞어도 안 없어진다.

## 남은 길 — 둘

### ① 루브릭 술어 정렬 (내 파일, 지금 가능)

무리 A·B 9개 항목의 조건에 정면 반박을 써 뒀다(`tools/condition_counters.py`, 21개).
**지금 판정에 안 쓰지만**, MiniCheck 식 학습을 하면 **조건 ↔ 반박 쌍이 곧 모순 라벨**이라
합성 데이터의 씨앗이 된다. `tests/test_condition_counters.py` 가 루브릭 실물과 대조한다.

### ❗쓰면서 나온 것 둘

**부정 표지 정규식이 두 번 빗나갔다.**

```
못한       만 보면  "받지 **못할** 수 있다"    를 놓친다
못[하할함해] 로 좁히면 "돌려받지 **못한다**"    를 놓친다 (못 + 한다)
→ `못` 뒤를 제한하지 않는다. 이 맥락에서 `못` 은 항상 부정 보조다
```

**조건 하나를 뺐다 — 한 문장에 두 극성이 있다.**

```
"원금은 보장되고 이자만 못 받는다"     「보장된다」 긍정 + 「못 받는다」 부정
→ 극성을 뒤집을 수가 없다. 억지로 쓰면 뜻이 반쪽만 반대가 된다
→ **먼저 쪼개야** 대조 대상이 된다 (`#367` 과 같은 모양: 한 조항에 사실이 둘)
```

`#367`(요소 하나에 사실이 둘)이 **요소 쪽 사례**였는데, **조건 쪽에도 같은 것이 있다**는
것이 이 작업에서 나왔다. 22개 중 21개만 남은 이유다.

### ② 도메인 소형 모델 (3주차 이후) — 종착지

기성 부품이 우리 축(정도·수량사·범주)을 안 덮는다는 것이 이 측정의 결론이다.
[MiniCheck](https://arxiv.org/abs/2404.10774) 가 같은 과제 모양에서 **합성 학습 데이터로
770M 모델이 GPT-4 수준·1/400 비용**을 냈다. 우리에 맞는 이유가 셋이다.

```
합성으로 학습    라벨 70건으로는 학습이 안 되는 제약을 우회한다. 상품 조건이 정형이라 궁합이 좋다
로컬 실행        proposal.md:419 — "외부 LLM API 를 그대로 호출하는 구조는 재위탁 문제를
                일으킨다. 국내 인프라와 전용 배포를 전제로 설계한 이유다."
                → **호출 비용 · 결정론 · 망분리가 한 문제다**
문장 단위        절 단위 분할과 맞물린다
```

한계: 영어 기준 학습이라 한국어 부정 처리가 미검증. **접근법을 참고해 한국어로 다시 만드는
쪽**이 현실적이고, `KLUE-NLI`(실제 한국어에서 만든 첫 NLI, CC-BY-SA)가 출발점이다.

### 준비물 — 이미 확인한 것

`kiwipiepy`(C++·로컬·결정론)가 필요한 신호를 태그로 분리한다.

```
발화                          부정      종결(EF)   전언
"원금은 보장되지 않습니다"          않/VX     습니다     -
"원금은 지켜지는 거죠?"            -          죠      -
"예금자보호는 안 된다고 하셨죠"      안/MAG      죠      O
"손실이 날 수도 있다는 거네요"       -         네요     -
```

`-네요`(깨달음) 대 `-거죠`(확인 요구)를 정규식으로는 앞 글자를 봐야 갈리는데 `EF` 태그로
정확히 뗀다. **전언(`-다고 하셨죠`)이 구조로 잡히는 것**도 값이 있다 — 판매자 발화 인용을
고객 자기 믿음과 갈라내는 자리다.

❗**다만 종결어미를 신호로 쓰는 것은 `#377` 이 닫힌 뒤다.** 지금 표본에서는 그 신호의
강도를 믿을 수 없다.
